# Query corpus forms

`motif query --corpus <words.tsv|weights.json|folder>[,<more>] forms where <expression>` (also `forms --where <expression>` or `forms --query-json <file|->`) lists the words of a plain word list that satisfy a query expression, with no project, Trial or parse. The corpus is read as for `query pairs`; the expression is the text form of `motif.query.v2`, over the columns `form`, `tokens`, `parse.state`, `shape`, `syllables`, `fold`, `initial:n` and `final:n`.

```powershell
motif query --corpus words.tsv forms where 'phon(Stop V Stop V)' --grammar project.fwdata
motif query --corpus texts/ forms --where 'env([V] / # _ Stop) and tokens > 2' --grammar project.fwdata --json
```

`phon` and `env` need `--grammar <path>`, the grammar file `pangloss serve` loads; PanGloss segments the words with its surface character table and names the natural classes. Without it they are refused with `query.phon-needs-grammar`. Rows come by token count then form, `--limit` (default 100) keeps the first; a cut says `TRUNCATED`. The header counts the words the grammar cannot segment and lists a sample; `--json` writes `motif.query.corpus-forms.v1` with each row's `matches`. See `query forms` for the pattern language.

`realizes(<morpheme>, attested)` finds the words that carry a morpheme in any surface form the grammar gives it. With `--grammar <path>`, PanGloss parses every word type of the corpus once with `batch --analyses --morph-spans` (PanGloss v0.34.0 or later; an older one is refused as `query.realizes-index-failed` with `needs-pangloss-v0.34.0`) and Motif keeps the result as a parse index under its cache folder (`SIL/Motif/cache/realizes-parse-index` in the user data folder), keyed by the grammar file, the corpus's word types and the PanGloss build; the first query writes "building parse index" to standard error and takes about a minute and a half on a large grammar, and later queries load the index in a few seconds. The index records, for each analysis, each morph's ids and the surface text PanGloss places it at, so a matching word gives the morpheme's own piece with nothing traced. A morph PanGloss could not place (a typed null such as `span_lost_by_rule`, `span_ambiguous_copy` or `compound_unsupported`), or whose spans do not add up to the word's surface, stands in as its whole word and the header says `piece_unplaced` or `piece_inconsistent`. With `--project <fwdata>`, Motif also reads that project's stored analyses (never writing it), and the forms from both sources are joined and labelled. The morpheme is `entry:msa` or one id (an analysis or form id), which need no project; a form such as `sfx:-an` (optionally led by `root:`, `pfx:` or `sfx:`) needs `--project` to name the entry.

The forms compile to one search over the words' surface text, anchored at the start for a prefix and the end for a suffix. The header says what was searched for, whether the set is complete, how many word types the parse index answered, how many pieces came from spans and how many words stand in whole, and that the search can over-match, because it reads characters and not the grammar's segments; each row names the forms it carries. A word the grammar cannot segment, a parse stopped at a limit, a word the batch gave no answer for and a missing or untrusted surface piece each make the set not complete, so `not realizes(...)` is refused as `query.realizes-negation-incomplete`. If PanGloss fails to parse the corpus, or what it wrote is malformed, the query is refused as `query.realizes-index-failed` with the error output or the line number. An unreadable cached index is deleted and rebuilt once, with a note on standard error, and the cache keeps the eight newest indexes. A morpheme found in no parsed word type is refused as `query.realizes-no-parses`. The tiers `possible` and `generated` parse and are refused as not yet available.

`realizes(<id>, possible)` asks PanGloss which phonological rules can change the morpheme (`effects`), drops the rules its form rules out, and lists "These N rules can change M" with each rule's environment. It searches the words for the written form and for every surface variant it can compute by applying the rule's replacement, and, for a rule it cannot apply by hand, for PanGloss's own pattern for the rule's target, narrowed to the morpheme's edge. The morpheme must be named by `entry:msa` ids and the grammar must be given (`--grammar` or `--project`). The set is not complete, and `not realizes(...)` is refused, when a rule is unknown, unprintable, non-local or a metathesis, or the written form is only part of the morpheme.

`realizes(<id>, generated)` picks real roots (or affixes, for a stem) from the project's lexicon whose edge satisfies each rule environment, two per environment (three with `--thorough`), plus a control that triggers nothing, generates the morpheme on each with PanGloss, and reads the morpheme's own piece of each surface from the engine's morph spans. Where the engine cannot place the morpheme, the whole word stands in, labelled `whole-word`. Each surface carries the rules that fired and the test root. An environment no real root satisfies is named as uncovered and the set is not complete.

## Readings, causes and retirement

With `--grammar <path>` the corpus is parsed once (the same cached parse index as `realizes`) and each word type gets its readings. Three things read them.

- `readings` is a number column: `forms where 'readings > 3'`. `parse.state` then comes from the parse, not the word list: `parsed`, `none`, `capped`, `timed-out`, `unsegmentable` or `failed`. Rows show the reading count.
- `--group-by cause` groups the matching words that have more than one reading by why, and returns `{groups:[{cause, detail?, benign, words, tokens, example:{word, readings:[{morphs:[{form, msa, text, entry, kind, gloss}]}]}}]}` (under `causes`). Each word gets its most specific cause, narrowest first: the structural kinds that any pair of its readings shows come first, then the kinds every differing pair must show, then the segmentation differences. In priority order: `lexicalised-vs-derived` (one reading has a single stem over a span another covers with a root plus derivational affixes), `same-morphs-reordered` (the same morphs in another order), `homophonous-affix` (readings differ only in inflectional affixes that spell the same but have different analyses, such as SM and OM; `benign:true`; a stem, a derivational affix or a morph of unknown class is never benign), `same-segmentation` (every reading cuts the word at the same places with the same text, and only the entry or analysis of some morphs differs; never benign; `detail` is `stems` for homograph roots, `affixes` when only affixes differ, `mixed` when both do or a class is unknown), `clitic-or-stem-split` (one reading has a single stem over a span another splits into several morphs, such as a stem and a clitic), `boundary-shift` (the same number of morphs cut at different places, or the same morphs at shifted spans), and `other`. A word with many homograph readings and one boundary-shifted reading is `boundary-shift`, the narrower claim. `--group-by cause` needs `--project <fwdata>` (or a `.fwdata` as `--grammar`): each morph then carries its entry, class and gloss, so a harmless homophone is told from a different root; without one it is refused with `query.readings-needs-project`.
- `only-via(entry:<guid>)` (JSON `{"only-via": {"entry": "<guid>"}}`) matches words that have a reading and whose every reading uses the morpheme; `msa:` and `form:` name an analysis or a form id. PanGloss's batch gives each morph its form and analysis ids but not its entry; an analysis belongs to exactly one entry, so `entry:` needs `--project` (or a `.fwdata` as `--grammar`) and is refused with `query.readings-needs-project` otherwise.
- `--what-if-retire <id>[,<id>...]` (ids as `entry:`, `msa:`, `form:` or a bare id) lists, for the matching words, `readings`, `readingsVia`, `readingsOther`, `lost` (every reading goes) and `reduced` (some stay), with type and token totals. It is an estimate read from the cached reading sets and is labelled `estimate: true`: confirm with a Trial. Words with a finished parse are counted in `affected`, `lost` and `reduced`, and a `reduced` word lists the readings that stay as `alternative`. A word whose parse was capped or timed out goes in its own `capped` count and a word the batch gave no answer for in `failed`, so the totals add up and nothing capped is called lost. An id that no morph of the parse carries (a bare entry id with no `--project`, a misspelt guid, an entry the project does not have) is refused with `query.retire-id-unknown`, never answered with zero. A morph whose analysis the project's lexicon lacks is counted in `readingsInfo.unknownMsa` and makes the result incomplete.

A word whose parse was capped, timed out or got no answer may have more readings than the grammar gives, so the header says `Readings: INCOMPLETE` and the JSON `readingsInfo.complete` is false; the counts are then lower bounds. `--group-by` and `--what-if-retire` need no `where`; with one they cover only the matching words, and `rows` still lists the matches.

## Several sources, groups, totals, samples and word files

- `--corpus` takes several sources as one corpus: repeat the flag or separate the paths with commas (a path that exists is never split). A source is a `.tsv` word list, a weights file (a `.json` file holding one object of form to whole-number count, such as `bible_h.weights.json`) or a folder of `.txt` files. The counts of a form are summed across the sources, so the corpus has each form once; with more than one source the header names each with its kind and its own type and token counts, and `corpus.sources` in the JSON carries them. `pairs` reads the same sources.
- `--group-by <column>[,<column>]` counts the types and tokens of every matching word per distinct value of one or two columns (`parse.state`, `readings`, `shape`, `syllables`, `fold`, `initial:n`, `final:n`, `tokens`, `form`) and returns `groups:{columns, groups:[{key, values, types, tokens}]}` with `totals:{types, tokens}`, groups by tokens then key. A word with no value in a column is keyed `(none)`; two columns key as `a | b`. `parse.state` and `readings` come from the grammar's parse when `--grammar` is given (`parsed`, `none`, `capped`, `timed-out`, `unsegmentable`, `failed`), and from the word list otherwise; `readings` needs `--grammar`. It needs no `where`; with one, only the matching words are counted. A grouping lists no rows unless `--limit` asks for some. `--group-by cause` is the separate readings grouping above and takes no other column.
- `--sum tokens` adds `totals:{types, tokens}` for the matching words without a grouping. Tokens are always counted in a grouping, so `--group-by parse.state --sum tokens` and `--group-by parse.state` give the same answer; `tokens` is the only sum.
- `--sample <n> [--seed <s>]` keeps n of the matching words, chosen by a hash of the seed and the form (default seed 0), so the same seed over the same matches gives the same words, whatever the corpus order or the frequencies; a smaller match set is kept whole, and a different seed draws a different set. `--limit` is a different thing: it shows the first rows by token count, the most frequent words, and is the way to see the top of the list. The sample is the rows (and the `--write-words` file) unless `--limit` is given; groups and totals still cover every match, and `matched` is the full count; the JSON says `sample:{count, seed, of}`.
- `--write-words <file> [--with-counts]` writes the matching words (or the sample), every one and not just the first `--limit`, one per line, or `form<TAB>count` with `--with-counts`, by tokens then form, in UTF-8 with no BOM. An existing file is never overwritten unless `--force` is given; without it the query is refused as `query.write-words-exists` and nothing is written. The file is written beside the target and moved into place, so a failure leaves no half-written file. The JSON says `written:{path, words, withCounts}`.

```powershell
# Tamil -க்காக, types and tokens, parsed against unparsed, in one command
motif query --corpus bible_h.weights.json --corpus bible_x.weights.json forms where 'form ~ ".*க்காக"' --group-by parse.state --sum tokens --grammar tam.fwdata
# 50 unparsed words of a pattern, chosen by seed, as a working set with counts
motif query --corpus a.tsv,b.weights.json forms where 'parse.state = none and form ~ ".*ப்பட்.*"' --grammar tam.fwdata --sample 50 --seed 7 --write-words work.tsv --with-counts
```

## Ordered morphs: `morph`, `seq`, `--count-by morph-seq`

`morph(<item>)` keeps the words with a reading that has the morph; `seq(<item>, <item>, ...)` keeps the words with a reading whose morphs match the items in that order. Both read the readings of the cached corpus parse, so they need `--grammar` (refused as `query.readings-needs-grammar` without it). Gaps between the matched morphs are allowed; `seq(a, b, adjacent=true)` (JSON `{"seq": {"items": ["a", "b"], "adjacent": true}}`, a single `morph` as `{"morph": "a"}`) or `--adjacent` for every `seq` of the query needs them next to each other. Each morph matches one item, so `seq(x, x)` needs two morphs. An item is one of:

- `entry:<guid>`, `msa:<guid>` or `form:<guid>`: the morph's entry, analysis or form id; a bare guid is an analysis or form id. `entry:` needs the project.
- `root:<form>`, `pfx:<form>` or `sfx:<form>`: a form in the project's lexicon, resolved to its entry exactly as `realizes` resolves it (`root:` takes a stem, the others an affix); a form of several entries or analyses is refused as ambiguous, and then `entry:` or `msa:` names the one. Needs `--project` (or a `.fwdata` as `--grammar`).
- `text:<surface>`: the surface text the morph occupies, ignoring case; needs no project.
- any other token, such as `CAUS` or `RECP`: a class token. It matches a morph whose entry gloss, class (`stem`, `derivational`, `inflectional`, `affix`) or PanGloss inflection type equals the token, ignoring case. The gloss and class come from the project's lexicon, so a class token needs `--project`; without one it is refused as `query.readings-needs-project`.

A class token matches gloss, class or inflection type exactly (case-insensitive, never a substring, so `CAU` does not match `CAUS`); it shares its namespace with the stem glosses, so prefer `root:` or `entry:` to name a stem. An item that matches no morph of any reading of the parse is refused as `query.seq-item-unknown`, never answered with zero (a misspelt `CUAS` is caught that way). `not morph(...)` and `not seq(...)` are refused as `query.seq-negation-incomplete` unless the corpus parse is complete (no capped, timed-out or unanswered word), because a capped word may hide the reading. `readingsInfo.complete` says whether it is.

`--count-by morph-seq` counts the distinct morph sequences of the readings that satisfy the query's `morph` and `seq` predicates (every reading when there are none; a `not`, a field or another predicate says nothing about a single reading, so it never removes one: `not seq(A, B) --count-by morph-seq` lists the sequences of every reading of the words without the sequence, including readings of other words that contain it, and `seq(A) or form = x` keeps every reading of a word that matches only the second branch). A sequence is written by its morphs in surface order, each as its text, then `/` and the entry gloss when the project gives one (`fany/do`, `ish/CAUS`, `an/RECP`). A word counts once per distinct sequence, however many readings give it. The JSON adds `morphSeqs:{complete, words, tokens, distinct, sequences:[{seq:[...], types, tokens, examples:[word]}]}`, by tokens; `--limit` (default 100) caps how many sequences are listed, `distinct` is how many there are, and `complete` is false when a capped or unanswered word may hide readings, so the counts are lower bounds. It needs no `where` and lists no rows unless `--limit` is given.

```powershell
# how many words carry root fanya + CAUS + RECP in that order, and in what exact chains
motif query --corpus swh.weights.json forms where 'seq(root:fanya, CAUS, RECP)' --count-by morph-seq --grammar swh.fwdata --project swh.fwdata --json
# the same chain with the morphs next to each other
motif query --corpus swh.weights.json forms where 'seq(root:fanya, CAUS, RECP, adjacent=true)' --grammar swh.fwdata
```

## A stem list: `realizes(@file, attested)` and `--by-morph`

`realizes(@stems.txt, attested)` reads one morpheme spec per line (the same syntax as the single argument: `entry:msa`, `entry:<guid>` or a bare entry id, which means any analysis of the entry as `morph(entry:)` does and needs `--project`, an analysis or form id, or `root:`, `pfx:`, `sfx:` and a form with `--project`; blank lines and lines starting `#` are skipped) and means any of them. One index parse serves the whole list, from the parse's spans; nothing is traced. A line whose morpheme no parsed word carries stands for no word and is listed in `realizes` with the reason `no-parses`, where a lone `realizes(M, attested)` would be refused; `not realizes(@file, ...)` over such a list is refused as `query.realizes-negation-incomplete`. A guid that no morph of the parse and no entry of the project carries is refused as `query.realizes-id-unknown`, never answered as `no-parses`; a refusal about one line names the file and the line number. A line is not trimmed of an inline `# comment`. An unreadable file is refused as `query.corpus-unreadable`, and a file with no spec as `query.corpus-invalid`.

`--by-morph` groups the matches per morpheme of a `realizes` query as `byMorph:[{morpheme, types, tokens, examples}]`, by tokens; every line of the file has a group, with zero for one no word carries. It needs a `realizes` predicate in the query.

```powershell
# the corpus forms of eleven Tamil stems, per stem
motif query --corpus tam.weights.json forms where 'realizes(@stems.txt, attested)' --by-morph --grammar tam.fwdata --project tam.fwdata --json
```

## A paradigm twin: `--twin`

`--twin <template>` rewrites each word the where's `form ~ "regex"` (or `form matches`) predicate matches, from the regex's capture groups, and describes the rewritten form, its twin. The template writes `$1` or `${name}` for a group, `$0` for the whole match and `$$` for a dollar sign (use `${1}2` before a digit). The first match is replaced where it stands and the rest of the word stays, as a substitution does, so `~` rewrites the matched span and `matches` the whole word. The regex is the first one not under `not`, with the same engine as the query: non-backtracking, which supports groups and named groups but not lookarounds or back-references. A template that names a group the regex lacks is refused as `query.twin-group-unknown`, and `--twin` with no such regex as `query.twin-needs-regex`.

The columns of a lone `--twin` are `twin.form`, `twin.tokens` (0 when the corpus lacks the form), `twin.inCorpus` (`true` or `false`), `twin.parse.state` and `twin.readings`. With several `--twin` the templates are `twin1`, `twin2` in the order given (`twin1.form`, `twin2.parse.state`). A word the regex does not match has no twin values. The columns work in `where` (`twin.inCorpus is false`, `twin.tokens > 10`), in `--group-by` (`parse.state,twin.parse.state`) and in the JSON rows as `twins:[{label, form, tokens, inCorpus, parseState, readings}]`. The parse columns need `--grammar`: the parse state of a twin that is a corpus word comes from the corpus parse index, and the forms the corpus lacks are parsed by one more batch over just those forms, cached like the corpus (more than 100,000 such forms is refused). Without `--grammar` the rows carry the form, tokens and `inCorpus` only.

```powershell
# which -ிலிருந்து words are stem gaps and which only lack the -ில் suffix form
motif query --corpus a.weights.json,b.weights.json forms where 'form ~ "(.*)ிலிருந்து$"' --twin '$1ில்' --group-by parse.state,twin.parse.state --grammar tam.fwdata
```
