# Trial a Proposal

Measures a Draft or finalized Proposal on a throwaway copy, producing a Dry Run and Assessments. Read negatives now parsing, positives lost, unfinished cases, other changes and counts before revising.

After Motif's own Apply, the next Trial captures a new Baseline by itself, so no step is needed. After a save made outside Motif, such as one from FieldWorks, a Trial queued from the window is refused with `change.refresh-required` until you capture a new Baseline with Refresh or `motif baseline capture`. The command `motif trial` measures the Baseline before it queues, so it captures a new one by itself after any save. The evidence is otherwise about a project that no longer exists.

While a Motif update is installing, the Trial is refused with `trial.update-in-progress` and exit code 3; try it again in a moment.

Name the words to try inline, or in a UTF-8 file with one word per line: `--words <file>` on the command line, `wordsFile` on the `motif_trial` tool. On the tool, giving both `words` and `wordsFile` is refused with `assess.words-ambiguous`; a file that is missing, unreadable or empty is refused with `assess.words-file-unreadable` or `assess.words-file-empty`.

Word files must be at most 8 MiB of valid UTF-8 text without NUL bytes; an initial UTF-8 signature is accepted. A larger file is refused with `assess.words-file-too-large`; invalid UTF-8 or NUL bytes with `assess.words-file-not-text`. Split a large list into smaller files, or save a non-text file as UTF-8 with one word per line, then repeat the call.

Trial summaries report `beforeOutcomes` and `afterOutcomes` with the same `capped` (work limit), `timedOut` (time safety net) and `skipped` counts as Assess. The `unfinished` Difference category includes words unfinished on either side and is not a stop count for one run.

The Trial compares total parser work in work steps with the Baseline over the same words, and says how many percent more or less work the Trial took. It lists up to five words requiring more than 5% extra work, each with its Baseline and Trial work steps and the Trial's work as a multiple of the Baseline's. A stopped search or missing work count makes the comparison unavailable. Words stopped at the work limit are listed apart from words stopped only by the time safety net, and a word stopped by both is listed under the work limit. Work counts are deterministic for the same parser, grammar, word and limits; the total word time is shown last and labelled time on this computer, because it changes with machine load.

When total parser work increases by more than 5%, the completed Trial reports a warning. This warning does not block the Trial.

The Trial also names grammar the parser dropped with only a warning, with each object's name and Motif id. A Trial is clean only when the check for dropped grammar ran and found none in what the Proposal adds or edits; the findings are the parser's listed drops, which name what was left out, and any other import warning or error, which is reported more generally; findings that only mark a rule as partial or a data gap are not dropped grammar and are left out. Findings the Baseline's own grammar already had are only counted, except a listed drop on an object the Proposal edits, which counts as the Proposal's. Dropped grammar in what the Proposal adds or edits makes the Trial not clean, and Apply then refuses with `apply.dropped-grammar` until it is fixed, in the Proposal or in FieldWorks, and the Proposal is tried again. If the parser could not check, or the check timed out, or the Baseline's own check was not available to compare with, or the Trial was made before this check existed, the Trial reports dropped grammar as not checked and is not clean: try the Proposal again. The stored result keeps at most 25 findings and counts the rest. The `motif_trial` summary carries these findings as `droppedGrammar`, right after the words that now parse wrongly.

When no Difference can be built, `motif_trial` still succeeds: `difference` is `null` and `differenceUnavailable` says why, while `droppedGrammar` is reported as usual. `code` is `no-matching-baseline-assessments` when the Trial has no Baseline Assessments to compare with, and `comparison-refused` when the two sets of Assessments cannot be compared; `reason` has the details. Try the Proposal again to produce a Difference.

`motif trial --wait` prints the job status only. Read the finished Trial with `motif proposal trial`, and add `--word-results` (last, after the proposal id) for one line per Trial word with its outcome and the readings the parser gave it, as forms with glosses; `--json` carries the same rows. It lists every Trial word, so name a short word list.
