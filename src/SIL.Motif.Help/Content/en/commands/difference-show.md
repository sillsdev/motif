# Read a saved comparison

`difference show` reads a comparison saved by `difference produce`. It always starts with the totals, the before and after table and the count of words in each category, then lists one page of words.

Choose the comparison with `--difference`, or give `--proposal` to read that Proposal's newest. A Proposal keeps one comparison per Text and reference, so add `--text` (a Text GUID) and `--reference human|source-validated` to read a particular one; they are refused without `--proposal`. The output says which Text and reference the comparison belongs to, and lists the Proposal's other saved comparisons the same way, newest first and at most 50 (the JSON has `Saved` and `SavedTotal`). A saved comparison whose stored summary can no longer be read is left out of that list and counted, with a line saying how many could not be read (`SavedUnreadable` in the JSON) and one line naming each by Text, reference and time (`SavedDamaged`), and the others still show. When every saved comparison of the Proposal is damaged, the command refuses with `difference.unreadable` and names each one by Text, reference and time instead of saying there is none; `difference produce` for one of them makes it again. Without `--difference`, the newest comparison that can be read is shown even when a newer one is damaged; `difference produce` for that Text and reference replaces the damaged one. Narrow the words with `--could-be-bad`, `--bucket` (a category code such as `delta.regression` or `delta.improved.unique`), `--before` and `--after` (an approval state such as `approved-unique`, `approved-with-alternatives`, `no-approved-match` or `no-parse`). Use `--limitation` to list only the words one side of which a limit held back (a code such as `capped`, `timed-out`, `projection-unavailable` or `parser-refused`); a word counts for a limitation that touched either side, as the totals do. Page with `--offset` and `--limit`; the default page holds 25 words and the maximum is 200.

A comparison counts every word of the Text but lists only the words that changed or fall in a category, and each before and after pair, category and limitation keeps its best 100 words, those with the most places in the Text first. A word kept by one group counts as listed in all of its groups, so a count can list more than 100 words. The totals, the table and the category counts are always the whole Text's. Where a list is cut, the output says how many words are listed and how many are counted but not listed (`WordsListed` on the response and `Listed` on each count in the JSON; a comparison saved before these existed lists every word). A count of words that are counted but not listed is never an empty list. A word that did not change and falls in no category is only counted. A listed word keeps at most 10 of its places, the first in reading order (line, then position in the line).

Give `--word` to list one exact word together with the places in the Text where it occurs, a page at a time: `--occurrence-offset` and `--occurrence-limit` (default 25, maximum 200), which are refused without `--word`. Each place has the Text, the line, the line's number and the word's position in the line. The places are word detail, so they are kept only while the Proposal is undecided and not deferred. A word with more than 10 places lists only the first 10: `Total` is how many places it has in the Text, `Listed` (in the JSON; absent when every place is listed) is how many can be paged, and the output says how many are counted but not listed. Paging stops at the listed places, and the rest of them are found in the Text itself.

When the Proposal has been applied, rejected, withdrawn, superseded or deferred, the word list is no longer kept; for a deferred Proposal, `difference produce` makes the comparison again to see the words. The command still succeeds: it shows the summary, no words, and says that word detail is no longer kept. In the JSON, `WordDetailKept` is `false`.

If the saved words of a comparison cannot be read, for example because their stored rows were damaged, the command still shows the summary, lists no words and says that the word detail cannot be read. In the JSON, `WordDetailKept` is `false` and `WordDetailUnreadable` is `true`. Run `difference produce` for the same Text and reference to make the comparison again.

Categories are advice about parses and recorded decisions. A word with no recorded approval shows only that its parses changed, and a search that did not finish never proves that a reading disappeared.

```powershell
motif difference show --project "C:\FieldWorks\Projects\Koro\Koro.fwdata" --proposal <proposalId> --could-be-bad --json
```
