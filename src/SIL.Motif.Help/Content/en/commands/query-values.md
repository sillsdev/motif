# Query values

`motif query --values classes --project <fwdata>` (or `--grammar <path>`) lists the natural classes and phonological features of the project's Baseline or of a grammar file: the names a `phon` or `env` pattern can use. The MCP tool `motif_query_schema` returns the same list with `values: "classes"`.

Each class line leads with the token to type in a pattern (in brackets when it has spaces), then PanGloss's label for the class and its kind: `segment` (an explicit segment list) or `feature` (a feature structure). The kind matters for matching: PanGloss tests literals and segment-list classes by identity (see `query forms`). PanGloss keeps one label per class (a FieldWorks project's Abbreviation; the Name FieldWorks shows is not kept), so a class is written by that label, case-sensitively, or by its id; a class whose label cannot be written in brackets shows `(none)`. Features list their values.

The list comes from PanGloss's `inventory` op, so it needs a PanGloss that declares `interfaces.serveOps.inventory` (release v0.30.0), starts the grammar once (a few seconds, where reading it with LibLCM took about three and a half minutes on a 170 MB project) and reads it as the parser loads it. When PanGloss refuses a name as `unknown_natural_class`, Motif reads the list, resolves a different case or an id to the class's token and tries again, or refuses with the closest (at most five) labels; if the list cannot be read or is empty the refusal says so. Text between `/.../` is never rewritten. `--verbose` prints the stage timing to standard error. The JSON gives each class a `token` and `kind` and each feature its `values`. `--json` writes `motif.query.values.v1`. See `query forms` for the pattern language.
