# Class contains extra segments

Extra natural-class members may be productive. Review every usage site, its Approved triggers, the feature intersection, and unknown membership before changing the class. A feature intersection is a deterministic set calculation, not a probability; it cannot show that an unobserved member is wrong.

## Analyse

Read `natural-class-excess` for each measured usage site, the current effective extension, observed triggers, missed triggers, feature-intersection extension, and unknown members. `approved-morph-sequences` contains aligned Approved words. The shared feature assignments determine the set of possible class members from the loaded chart; this calculation has no sampling model and is not a probability. Missing feature values remain unknown, and a class may intentionally generalize beyond its current observations.

## Disposition

An applied keep or defer is tied to this finding's exact evidence. See [Disposition](term:disposition) for how it appears in Active and Suppressed lists and returns after relevant evidence changes.

Fix only an independently reviewed leak; keep a productive extension with a reason; ask for contrasts; defer incomplete feature or context attribution. The measure reports definite extras at a uniquely attributed site, including sparse support, and makes no automatic change. A p-only observation with held-out b and m positives supports keeping B={p,b,m} when those members remain productive.

## Ask the linguist

Ask whether the process applies to the additional segments and request independent examples, not endorsement of the smallest observed set.

## Update

Use `EditNaturalClass` to change the segment members of one explicitly scoped class. Its review lists every environment, rewrite rule, and morphological insertion that uses the class. When users have different meanings, use `AuthorNaturalClass` to create a separate class and `RelinkNaturalClass` to move only the confirmed typed environment or rule contexts. The other users stay on the original class. Neither route changes a feature chart.

## Verify

Use Review changes to inspect what the edit would write, then compare parser results from the current and edited scratch copies for the same words. A confirmed correction must make the reviewed wrong form complete with no accepted reading, preserve every Approved reading, and retain valid held-out positives such as b and m. For a relink, verify the intended user changes and the other users still parse through the original class. A Keep records its reason against the finding evidence and makes no grammar edit. The view reports the definite feature-intersection extension and unknown members; when membership is unknown, do not claim an exact excess rate or a tightest class. If class extension or unique context attribution is unavailable, name it and defer.
