# LCModel lives in a separate adapter package

`SIL.TextEditing` and `SIL.TextEditing.Avalonia` never reference LCModel. A third package, `SIL.TextEditing.LCModel`,
converts between `ITsString` and runs and reads and writes FieldWorks' "TsString" clipboard XML. Only the LCModel-side
code of FieldWorks and Motif references it.

This keeps three things working. FieldWorks' `EngineIsolationAuditTests` forbids direct LCModel references from
FwAvalonia. Motif's GUI reaches LCModel only through its host project. The playground and headless tests run without
a project.

Owner decision, 2026-11-03.

Refined 2026-11-04: the clipboard forms, and the order paste reads them in, are in ADR 0029.

Amended by ADR 0031 (2026-11-05): `SIL.TextEditing.Project` may also reference `SIL.LCModel`, at FieldWorks' pin (hosts may float up). It is not trimmable or AOT-marked, as this adapter is not; the library still has no Avalonia or liblcm reference in the core projects.

Amended 2026-11-05 (issue 136): the adapter never hands liblcm a property its reader refuses by number (the amendment for issue 139, below, extends this to values). liblcm's text-props XML writer writes some integer properties that its reader then rejects ("Unknown Prop attribute"), and FieldWorks reports a project holding one as a corrupted record. Reproduced against the real serializers in `LiblcmRefusalSweepTests`: hyphenate (150), maxLines (151), cellBorderWidth (152), cellSpacing (153), cellPadding (154), setRowDefaults (159), relLineHeight (160), directionDepth (129) and ktptMarginTop (50, written `MarginTop`, read only as `marginTop`) throw on read; ktptEditable (155) throws in a paragraph's StyleRules and is ignored on a run. Defaults:
- The opaque bag rule stands: the run model carries these properties unchanged through every edit. The refusal is at the adapter's output only. `ToTsString`, `ToStyleRules`, `ToTextParagraphs` and `FragmentToXml` leave a refused property out of the `ITsString` or StyleRules they build and report each one to an optional `Action<DroppedProperty>` (id `textediting.lcm.unstorable-property`, or `textediting.lcm.replaced-property` when the value was replaced, below; with the paragraph, the run and a `Reason`; a copy through `TsStringClipboardForm` reports to its `OnDropped`). With no callback they still drop, silently; they never throw. The host decides whether to show a finding. Markdown `p<N>` attributes and a pasted `ITsString` can put these properties in a bag, so the one filter at the adapter covers both.
- A property liblcm silently loses (ktptTableRule 161, unknown numbers, tabList, tabDef, legacy charStyle and paraStyle) is not refused. It cannot corrupt a project, so it stays on the output; liblcm's own save loses it, and the bag keeps it for in-memory uses. A host that must persist such a property needs its own storage. "Cannot corrupt" holds for a Release liblcm: its reader calls `Debug.Fail` on tabList, tabDef, paraStyle, wsStyle and charStyle, so a Debug build of liblcm asserts when it loads one (the NuGet package is a Release build, and the sweep tests run against it).
- The refused list is a fact about liblcm. One sweep test (`LiblcmRefusalSweepTests`) ties `LiblcmRefusals` to what the real serializers do, so there is no second list to keep: when liblcm changes, it names the property and value, and the rule changes with it.

Amended 2026-11-05 (issue 139): liblcm also refuses some values of properties it otherwise loads: its reader throws, its writer throws, or a value it read cannot be saved again. Found by sweeping property numbers 1 to 300 with a spread of variations and values through both serializers (a paragraph's StyleRules, and a string's runs), each a write, a read and a save of what was read. The adapter leaves such a value out at the same four hand-off points, reports it through the same callback (`DroppedProperty.Reason` is `ValueNotLoadable`, with a `Detail`) and never throws; the bag keeps it. Markdown reaches these (`{rightToLeft=-1 padTop=-5}` puts them in the bag with no finding). The refused values:
- Enums: bold (3), italic (2), superscript (4) and spell check (26) take 0, 1 or 2; underline (5) takes 0 to 6; alignment (17) 0 to 5.
- Negative: font size (6), leading and trailing margin (19, 20), rightToLeft (128), paddings and borders (134 to 141), bulNumScheme (143), bulNumStartAt (144; the minimum integer means unset and loads), keepWithNext (148), keepTogether (149) and widowOrphan (162). First indent, space before and space after (18, 21, 22) may be negative.
- Variation: font size takes variation 0 to 2; offset (7) and line height (24) take 1 or 2 only. A run's offset cannot be negative (liblcm's props reader allows it, its run reader does not). Line height cannot be the minimum integer.
- Strings written as text (fontFamily 1, charStyle 2, paraStyle 3, tabList 4, fontVariations 130, namedStyle 133, the bullet texts 145 and 146) throw on write when they hold a character XML cannot carry: controls other than tab, line feed and carriage return, lone surrogates, U+FFFE and U+FFFF. This includes the properties liblcm ignores on read, because its writer still runs. Text after a NUL is cut off silently, which is a loss, not a refusal.
- Tags (5) are 16-byte GUIDs; fewer than eight characters loads and then throws on the next save. Object data (6) of the GUID types (link, own link, context string, moveable object) needs eight characters after its type; the path and embedded types need XML-safe text.
- BulNumFontInfo (147) and WsStyle (156) are packed records written by the text-props writer only (a run does not write them). Many malformed values throw; the adapter asks liblcm (write, read, save) instead of copying the layout.
- One exception to "left out": a refused rightToLeft (128, say `-1`) in a paragraph's bag, where the model also holds the direction as `Paragraph.Rtl`. `ToStyleRules` stores `Rtl ? 1 : 0` so liblcm keeps what the editor shows, and reports it with `DroppedReason.ValueReplaced` under its own id, `textediting.lcm.replaced-property`: the property is not left out, so a host that counts unstorable findings does not count it (`DroppedProperty.Id` picks the id from `Reason`). Direction is the only property with a typed field besides the style name, and a refused style name has no safe substitute, so it is left out.
- Not refused: a colour out of range and a negative relative line height (read as its absolute value) load, changed. A `-1` variation with a `-1` value is a delete to the property builder, so nothing reaches liblcm. The writing system (1) and base writing system (16) depend on the host's handles and are not judged here.
- The packed-value check (147, 156) asks liblcm to write, read and save the value through a permissive writing-system shim, where every handle names a writing system. It judges the shape of the record only. A real project's writing-system factory may refuse a writing system it does not know, so a packed value that passes here can still fail to load in a project that lacks that writing system; the adapter cannot know the project's writing systems.
- `LiblcmRefusals` and `Refusal` are internal. The public surface is `TsStringConversion.IsRefusedByLiblcm` (the one number check), `DroppedProperty`, `DroppedReason` and the `OnDropped` callbacks. The sweep covers object-data type characters 0 to 255 and reports every mismatch.
