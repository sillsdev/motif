# 0098. ChatGPT reaches Motif through a bundled tunnel-client

ChatGPT can connect to a running Motif installation without the person exposing their computer as a public server. Motif starts a bundled tunnel client only when asked and stops it when the window closes.

**Status:** accepted, 2026-11-09; no hands-on ChatGPT account test was authorized (owner Q31).

## Decision

ChatGPT needs a remote MCP endpoint while Motif's MCP server communicates over standard input and output. Package a pinned OpenAI `tunnel-client` and its adjacent cloudflared companion in the Velopack payload. On Connect, Motif starts its own hidden, uncatalogued `motif tunnel-supervise` process for each `init` and `run` invocation. The supervisor starts the bundled tunnel client, forwarding its output, and the client wraps the adjacent `motif mcp` using a private temporary local-stdio profile. On Windows the supervisor assigns itself to a kill-on-close Job before creating the tunnel, so the child inherits membership. On Unix the supervisor creates a separate session and process group before starting the tunnel; its descendants inherit that group. Linux also makes the supervisor a child subreaper. On all platforms the supervisor watches the owning Motif PID and process start identity, and stops the tunnel tree when the owner dies, its input closes, or the tunnel exits. On Unix cleanup sends SIGTERM to the group and follows with SIGKILL after a grace period only while the leader's recorded start identity still matches. If the leader cannot be verified, it enumerates the group and signals members individually only when their resolved executable is inside the recorded bundled tunnel-client directory. Linux uses /proc process-group and executable information; macOS uses proc_listpgrppids and proc_pidpath (declared by [Apple libproc](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.h)). Linux uses kernel process-start ticks so identities agree across processes.

As a fallback, Motif keeps one locked run record per owner containing owner PID and start identity and the tunnel PID, start identity and actual executable path. On Unix the record also identifies the process group, its leader start identity and the resolved bundle directory, and is created before the tunnel starts. At startup and before Connect it recovers only a dead owner's matching group; a live owner is never interrupted, and recovery is independent of the current installation path. While the leader remains verified, records remain until the group has no live members. With an unverifiable leader, only verified bundled executables are stopped and the record is dropped once none remain; unrelated members are left alone. Disconnect, desktop-session close and unexpected supervisor exit use the same identity checks. On Windows the Job stops the supervisor and its tree. Tunnel-client restarts a failed stdio child by default; Motif does not automatically restart a failed tunnel process. A later explicit Connect starts a fresh process. Do not run two clients for the same tunnel ID: stdio MCP sessions are not routed between replicas.

The OpenAI runtime key has Tunnels Read and Use access. Store it only in Windows Credential Manager, macOS Keychain or Linux Secret Service. Pass it through the supervisor to the tunnel process in `CONTROL_PLANE_API_KEY`, never in arguments, Motif files or logs. On Linux, if libsecret or Secret Service is unavailable, retain it only in process memory and tell the person it must be entered again next time. Do not persist a literal key in the profile; it names the environment variable instead.

The package includes tunnel-client's Apache-2.0 licence and NOTICE, cloudflared's Apache-2.0 licence information and upstream third-party licence report. Pin each supported archive and verify its SHA-256 before extraction; a missing pin blocks packaging. Preserve the two executables adjacent to one another. Sources: https://developers.openai.com/api/docs/guides/secure-mcp-tunnels and https://github.com/openai/tunnel-client/blob/master/docs/configuration.md.
