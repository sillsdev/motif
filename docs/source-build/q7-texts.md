# Q7: texts and per-occurrence analyses in a CRDT (facts)

Paths: IX = /mnt/h/repos/interlinearizer-extension, LCM = /mnt/h/repos/liblcm/src/SIL.LCModel, H = ~/work/research-src/harmony, LB = ~/work/research-src/languageforge-lexbox.

## Headline
The interlinearizer does NOT keep texts in Harmony. Only analyses and links are CRDT objects. The Book/Segment/Token hierarchy is rebuilt from USJ on every load (IX/AGENTS.md:227, VERIFIED). A token has no entity and no GUID: a token's identity is a derived string "BOOK ch:vs[/heading]:charStart" (IX/c-sharp/InterlinearizerCrdt/Entities/Refs.cs doc comment; IX/docs/reanchoring.md:3, VERIFIED). So there is no precedent to copy for "texts in the CRDT".

## 1. Interlinearizer model in Harmony (all VERIFIED)
- Entities (IX/c-sharp/InterlinearizerCrdt/Entities/): InterlinearProject, TokenAnalysis, PhraseAnalysis, SegmentAnalysis (free translation), plus links TokenAnalysisLink, PhraseAnalysisLink, SegmentAnalysisLink. Each has Create/Patch/Replace changes (Changes/*); project has Create/Patch (and delete). No Book/Segment/Token/Morpheme entity: MorphemeAnalysis is a record stored as JSON inside TokenAnalysis.Morphemes (MorphemeAnalysis.cs; AGENTS.md:91 "Owned values").
- Approval is a field, not a type: `AnalysisLink.Status` = approved | suggested | candidate | rejected | stale (Enums.cs). Also Confidence (high..guess), Producer (free tag), SourceUser (Analysis.cs).
- Shape: a payload (TokenAnalysis) is shared by every occurrence analysed identically; a link (one per token) points at it via AnalysisId (AGENTS.md:~237; Analysis.cs AnalysisLink). Deleting a payload cascades to its links via GetReferences/RemoveReference (Analysis.cs).
- Token identity and re-anchoring: link carries TokenSnapshot(TokenRef, SurfaceText) (TokenSnapshot.cs). TokenRef embeds verse + UTF-16 char offset. Edits shift offsets, so IX/docs/reanchoring.md describes a pass (LCS alignment per verse, normalised form) that rewrites link refs; unplaceable approvals become `stale`, placed stale ones revive. Stable synthetic token ids were explicitly rejected (reanchoring.md:11-13). Known silent-wrong cases are listed (reanchoring.md "Known limits"): deleted word with unglossed twin; insertion that shifts a twin onto a glossed offset; cross-verse moves go stale.
- Morpheme to lexicon: MorphemeAnalysis has EntryRef, SenseRef, AllomorphRef, GrammarRef (MorphemeAnalysis.cs). Each is (Authority, ProjectId?, string id) (LexiconRefs.cs). Authority "fw-lite" gives one id space across FwData and CRDT copies (IX/src/utils/lexicon-authorities.ts:10). Resolved only at display via the Lexicon extension's `lexicon.entryService` (getEntries/getSense/addEntry, IX/src/types/lexicon-extension.ts:56-71). Nothing validates the GUID at write time. AllomorphRef/GrammarRef cannot resolve today: LexBox #2558 (IMoForm) and #2559 (MSA) are OPEN (MiniLcm has no allomorph or MSA model).
- Store granularity: one SQLite per SOURCE Paratext project (`<sourceProjectId>.sqlite`, OpenSources.cs:61), holding many InterlinearProjects, each record stamped with ProjectId (AGENTS.md:86-87). Not per book. (The older TS draft storage is per-book shards; the CRDT one is not.)
- No order field anywhere in the entities (grep "Order" in the CRDT project finds only a doc comment).

## 2. LCM model of the same thing (VERIFIED from LCM/MasterLCModel.xml)
Chain: StText.Paragraphs (owning seq of StPara, :478) -> StTxtPara (:505: Contents string, ParseIsCurrent, owning Segments seq at :543, AnalyzedTextObjects) -> Segment (:259: BeginOffset int, FreeTranslation, LiteralTranslation, Notes, Reference, media/time offsets, and `Analyses` = reference SEQUENCE of IAnalysis, :268). Segment.BaselineText is a substring of paragraph Contents from BeginOffset (OverridesCellar.cs:4397). There is no CmBaseAnnotation in this chain: an occurrence is positional, `AnalysisOccurrence(Segment, Index)` (DomainServices/AnalysisOccurrence.cs:25-45). So occurrence identity is (segment GUID, index into AnalysesRS); no per-token object exists.
- IAnalysis implementers: WfiWordform, WfiAnalysis, WfiGloss, PunctuationForm (InterfaceAdditions.cs:299, 2591, 2700, 2708). An occurrence points at any level: wordform = unanalysed, WfiAnalysis, or WfiGloss.
- WfiWordform (:3954, ownerless): Form (MultiUnicode), owning Analyses (collection), SpellingStatus, Checksum.
- WfiAnalysis (:3909): Category (POS ref), MsFeatures, Stems (refs), owning Meanings (WfiGloss collection), owning MorphBundles (SEQUENCE), CompoundRuleApps and InflTemplateApps (ref seqs), Evaluations (ref collection of CmAgentEvaluation).
- WfiGloss (:3946): Form MultiUnicode. WfiMorphBundle (:4713): Form, refs Morph (MoForm), Msa, Sense, InflType.
- Approval: CmAgent (:672: Name, Human bool, owning atomic Approves :698 and Disapproves :703, each a CmAgentEvaluation). A WfiAnalysis is approved or disapproved by an agent by listing that agent's Approves/Disapproves object in its Evaluations; no opinion = no evaluation (InterfaceAdditions.cs:2388-2395; Opinions enum disapproves=0, approves=1, noopinion=2, Enumerations.cs:761). Human = LangProject.DefaultUserAgent; parser = DefaultParserAgent (InterfaceAdditions.cs:841-851). "Parser-approved" = eval whose owning agent is non-Human and Approves (OverridesLing_Wfi.cs:1249-1252). Wordform exposes HumanApprovedAnalyses / HumanNoOpinionParses / HumanDisapprovedParses (OverridesLing_Wfi.cs:650-667, 1420). IMPORTANT: approval in LCM is per ANALYSIS (type level, per wordform), and the per-occurrence "this token means this analysis" is the segment's AnalysesRS entry. There is no per-occurrence rejected/stale status like the interlinearizer's.

Benchmarks exist with params up to 10k/100k commits for sync-state (H/src/SIL.Harmony.Benchmarks/GetSyncStateBenchmarks.cs:14, BuildSyncStateBenchmarks.cs:12) and 1k/10k for snapshots and sync (AddSnapshotsBenchmarks.cs:51, DataModelSyncBenchmarks.cs:46); no published results, no docs on 700k objects. 700k tokens is above every benchmarked size. Checkpoints exist (SnapshotCheckpointPolicy, report harmony.md). VERIFIED absence; replay time at that size UNKNOWN.
- Interlinearizer perf: perf harness tiers up to "large" = every WEB-sample book at 50% gloss coverage, and a loadable whole-Bible tier at 30% (IX/perf/dataset/tiers.ts). These measure the old per-book JSON shard store and the app, not Harmony; the "large" draft exceeds one websocket message (tiers.ts comment). The CRDT store only holds analyses (not tokens), so its object count is gloss coverage x tokens, shared payloads reduce it. Handling at scale: lookup columns (BookCode, NormalizedForm) avoid reading JSON (AGENTS.md:93); indexes built ahead of first command; whole-text read only on demand (AGENTS.md:149); re-anchor per book as books are read.
- Order: Harmony's `double Order` (SetOrderChange, H/src/SIL.Harmony/Changes/SetOrderChange.cs:7-16, midpoint insert) is NOT used. Interlinearizer order = position in USJ text plus char offsets in the ref. Precision exhaustion from repeated midpoints is arithmetic inference (harmony.md), untested. For texts in a CRDT you would need Order (or similar) for paragraphs, segments and tokens/occurrences; no existing code does that.

## 5. Edge cases
- Concurrent USJ edits vs anchors: in the interlinearizer there is no concurrency, since text is external and re-anchoring is a pass over local state; two clients running passes and merging is explicitly unresolved (#601 "before sync ships"). Link edits merge field-wise (patch = last writer; patch fields unset left alone, AGENTS.md:88-90).
- Paratext as owner: the design assumes it. USJ is fetched from PT via PAPI; imported PT9 projects are read-only and never healed (reanchoring.md). If Motif stored text in a CRDT, a text copy would be a second source of truth; the interlinearizer rejected exactly that (reanchoring.md:12).
- Same word in two texts sharing one analysis: interlinearizer shares payloads across occurrences within a project, found by NormalizedForm (AGENTS.md:~237; suggestion engine uses a surface-form index, interlinearizer.md section 5). LCM shares one WfiAnalysis per wordform across all texts by design (owning Analyses on the wordform). Shared payload means one approval-value edit changes every occurrence's meaning unless a new payload is made.
- Deleting an analysis that occurrences point to: interlinearizer cascade-deletes the links (AnalysisLink.RemoveReference); #641 and #628 (OPEN) are about reporting cascades and refusing local edits that cascade; synced commits still cascade silently (#601 line 23, VERIFIED). Harmony also revives a deleted record on a later put under its id (AGENTS.md:101). LCM side: Segment.AnalysesRS is a reference sequence, so removal of the target is handled by LCM's reference cleanup (INFERRED, not traced); WfiAnalysis deletion with Evaluations updates approval lists (OverridesLing_Wfi.cs:1428-1436).

## Consequences for the mapping (INFERRED)
- Smallest-CRDT mapping that matches both models: keep text outside (PT/USJ or .fwdata paragraphs); put in the CRDT only (a) wordform/analysis payloads keyed by GUID, (b) per-occurrence links keyed by an occurrence key, carrying status. The hard decision is the occurrence key: LCM uses (segment GUID, index), interlinearizer uses (verse, char offset) plus surface snapshot. Neither is stable under text edits; the interlinearizer accepts staling, LCM's AnalysisAdjuster (DomainImpl/AnalysisAdjuster.cs) rewrites AnalysesRS on text edits.
- Building .fwdata from this requires generating StTxtPara/Segments from USJ and AnalysesRS from links; interlinearizer's per-occurrence rejected/stale statuses and token-level shared payloads have no LCM equivalent beyond Approves/Disapproves on the WfiAnalysis (type level).
