## Findings

### P2 — A refused item in a bulk Analyze Texts action can become an unreported partial result

**Verified code path:** The “Add readings as Unknown in all chosen Texts” action iterates readings and awaits each staging request, but ignores its Boolean result in [ResultsInTextViewModel.Scopes.cs:123](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/ResultsInTextViewModel.Scopes.cs:123). `PutAsync` returns `false` for a refused request and reloads after a revision conflict in [ChangesViewModel.cs:138](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/ChangesViewModel.cs:138) and [ChangesViewModel.cs:223](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/ChangesViewModel.cs:223). A later successful request assigns `outcome.Refusal`—null on success—to `LastRefusal` in [ChangesViewModel.cs:376](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/ChangesViewModel.cs:376). The UI presents the operation as applying across all chosen Texts in [ResultsInTextPanel.axaml:81](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/Views/ResultsInTextPanel.axaml:81).

**Scenario (inference from that verified path):** Another Motif process changes the pending revision between words. One word’s staging request is refused; the conflict path reloads the snapshot and returns failure. The loop continues, later words can stage successfully, and that success clears the earlier refusal. The user is left with a partial set and no refusal explaining why. The spelling bulk loop also discards staging outcomes because `AddFromTextAsync` returns no success value at [ResultsInTextViewModel.Scopes.cs:150](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/ResultsInTextViewModel.Scopes.cs:150).

**Proposed fix and test surface:** Propagate per-item results and stop on the first refusal in the iterative scope actions; make `AddFromTextAsync` return its staging outcome. Preserve the refusal through the action’s completion. Add a scripted outcome test—success, typed revision conflict, success—that asserts the loop stops, the partial state is visible, and the refusal remains. Extend the scope tests beyond the current removal-only theory in [AnalysisOperationScopesTests.cs:21](C:/Users/johnm/Documents/repos/motif/tests/SIL.Motif.Tests.App/App/AnalysisOperationScopesTests.cs). Whether bulk actions should instead stage all operations atomically is a separate owner decision; the current UI does not promise or implement all-or-nothing staging.

### P2 — Current window copy and guides contradict the accepted opinion vocabulary

ADR 0049 says the window uses Approved, Disapproved, and Unknown, and never says Rejected or Candidate in [0049-fieldworks-opinions-and-now-after-apply.md:27](C:/Users/johnm/Documents/repos/motif/docs/adr/0049-fieldworks-opinions-and-now-after-apply.md). The current Matrix UI still exposes “Reject” and “Back to candidate” in [ComparePanel.axaml:272](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/Views/ComparePanel.axaml:272) and [ComparePanel.axaml:275](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/Views/ComparePanel.axaml:275); the latter stages the Unknown opinion, as shown by [AnalysisMarkingState.cs:342](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/AnalysisMarkingState.cs:342). The Analyze texts guides also list “Reject reading,” “Back to candidate,” and “Add parser readings as candidates” in [texts.md:5](C:/Users/johnm/Documents/repos/motif/help/en/guide/texts.md:5) and repeat that list in [change-an-analysis.md:3](C:/Users/johnm/Documents/repos/motif/help/en/guide/change-an-analysis.md:3). Live Analyze Texts choices include “Disapprove,” “Make Unknown,” “Add as Unknown,” and “Add as Approved” in [AnalysisMarkingState.cs:332](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/AnalysisMarkingState.cs:332) and [AnalysisMarkingState.cs:356](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.App/ViewModels/AnalysisMarkingState.cs:356).

**User effect:** Someone can choose “Back to candidate” and then see the resulting opinion presented as Unknown. The guide’s bolded action names also do not match the controls a user is asked to find.

**Proposed fix and test surface:** Bring visible and automation names into line with ADR 0049—such as “Disapprove” and “Make Unknown”—and update both guides to the actual action vocabulary. Add a headless assertion for the visible caption, automation name, and resulting staged opinion; add a help-content check for the approved terminology. Keep the English help source in `help/`, which the CLI, window, and site share; avoid adding a second site-only copy.
