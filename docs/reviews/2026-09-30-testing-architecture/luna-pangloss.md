## Findings

1. **P2 — Captured parser output has no byte limit.**  
   **Verified:** The invoker starts concurrent stdout and stderr drains, which avoids pipe deadlock, but the Windows adapter reads each stream completely into managed strings ([PanGlossInvoker.cs:204–207](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/PanGlossInvoker.cs:204), [WindowsCpuJob.cs:225–226](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/WindowsCpuJob.cs:225)). On Unix, output goes to temporary files and is then read completely into strings ([UnixPanGlossJob.cs:183–185](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/UnixPanGlossJob.cs:183), [UnixPanGlossJob.cs:324–331](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/UnixPanGlossJob.cs:324)). Stats intentionally use stdout ([PanGlossRequest.cs:136–137](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/PanGlossRequest.cs:136)).  
   **Scenario:** A parser bug or runaway diagnostics produces very large output. On Windows, Motif retains it in memory; on Unix, the temp volume can fill, followed by an in-memory copy. The child’s memory cap does not bound Motif’s capture memory or disk use.  
   **Fix and test surface:** Give stdout and stderr explicit byte budgets. Keep draining both streams, but terminate the contained process on budget overflow and return a typed incomplete/refused outcome that cannot produce an Assessment. Test oversized stdout and stderr concurrently, assert bounded capture and temp cleanup, and assert no Assessment is committed. The existing 1 MiB stderr test checks deadlock handling, not boundedness ([PanGlossInvokerTests.cs:204–216](C:/Users/johnm/Documents/repos/motif/tests/SIL.Motif.Tests.Commands/PanGlossInvokerTests.cs:204)).

2. **P2 — Some Batch invocations have no wall-clock deadline.**  
   **Verified:** `ResolveWallClockCap` returns `Timeout.InfiniteTimeSpan` for a Batch request without a per-word limit ([PanGlossInvoker.cs:101–104](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/PanGlossInvoker.cs:101)). Assess can produce that request when it has no per-word estimate ([AssessCommand.cs:192–199](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Commands/Assess/AssessCommand.cs:192)). A test explicitly requires the infinite deadline while retaining cancellation behavior ([PanGlossInvokerTests.cs:446–468](C:/Users/johnm/Documents/repos/motif/tests/SIL.Motif.Tests.Commands/PanGlossInvokerTests.cs:446)). This conflicts with ADR 0044’s stated deadline for every invocation.  
   **Scenario:** A first Assessment hangs in the parser without the caller cancelling. It can retain a machine admission slot indefinitely and hold up queued work. Cancellation and OS resource containment reduce impact but do not provide the missing deadline.  
   **Fix and test surface:** Apply the ADR’s finite default invocation deadline independently of the optional per-word limit. Test an unlimited-per-word Batch with a hanging fake: deadline expiry must kill the contained process, release admission, and yield no Assessment. Because current code and a test encode the exception, confirm whether that was intended to amend the ADR; no such accepted amendment was found in the ADRs inspected.

3. **P2 — Unix capture-file privacy depends on host creation policy.**  
   **Verified code; conditional risk is an inference:** Unix capture files are created under the system temp directory without an explicit `UnixCreateMode` ([UnixPanGlossJob.cs:183–185](C:/Users/johnm/Documents/repos/motif/src/SIL.Motif.Host/PanGloss/UnixPanGlossJob.cs:183)). They contain parser stdout/stderr. Without an explicit mode, Motif does not guarantee owner-only access; actual permissions depend on runtime and host policy. Linux file creation permissions are affected by the process umask or parent default ACL ([Linux `umask(2)` manual](https://man7.org/linux/man-pages/man2/umask.2.html)).  
   **Scenario:** On a Unix host whose creation policy grants group or other read access, another local account can inspect live parser output.  
   **Fix and test surface:** Set `FileStreamOptions.UnixCreateMode` to owner read/write when creating these files; .NET documents this property for setting new-file mode ([Microsoft `UnixCreateMode` documentation](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestreamoptions.unixcreatemode?view=net-10.0)). Test the mode on Linux and macOS while a fake parser is still writing. I did not verify resulting modes on those operating systems.

## Positive observations and interfaces

- **Deep central invocation module:** `IPanGlossInvoker` exposes typed outcomes; `PanGlossInvoker` validates, queues, preflights, contains execution, and maps cancellation. Requests are built through typed `PanGlossRequest` factories rather than scattered shell strings. The concurrent stream drains are also the right deadlock-resistant shape; Microsoft documents the need to read redirected streams concurrently ([Process.StandardOutput documentation](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.standardoutput?view=net-10.0)).
