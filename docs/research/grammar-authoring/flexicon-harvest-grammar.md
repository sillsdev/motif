# Grammar authoring from Python tooling

This harvest records how the inspected Python tools create FieldWorks grammar data and what their source does—and does not—show about parser behavior. It extends [`docs/flexicon-harvest.md`](../../flexicon-harvest.md), which already covers transaction boundaries, deletion closure, normalization, and several ownership hazards.

The source snapshots are pinned so the citations remain reviewable: [Flexicon](https://github.com/MattGyverLee/flexicon/tree/d0a794c2da96e4029b875ce4e0f129d3461e7b9d) at `d0a794c2da96e4029b875ce4e0f129d3461e7b9d`; [flexlibs](https://github.com/cdfarrow/flexlibs/tree/3ee88f536945037671a94fde9a42ce0936865d41) at `3ee88f536945037671a94fde9a42ce0936865d41`; [FLExTools](https://github.com/cdfarrow/flextools/tree/b22d4141c8e598270096d4404c1b524cff83daf7) at `b22d4141c8e598270096d4404c1b524cff83daf7`; and [FlexToolsMCP](https://github.com/MattGyverLee/FlexToolsMCP/tree/4d5474a1bae1944be238448e8ff4cc6f826f856c) at `4d5474a1bae1944be238448e8ff4cc6f826f856c` (2026-09-28). Links below point to those commits. Flexicon is the primary writer here; flexlibs is a lower-level Python convenience layer, FLExTools hosts user-authored modules, and FlexToolsMCP indexes APIs and runs scripts. MCP can still execute direct LibLCM code, so absence of a dedicated wrapper is not evidence that LibLCM cannot represent a shape. ([FlexToolsMCP README: 232–245](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/README.md#L232-L245))

This is a description of source behavior, not a recipe for copying code. Flexicon is LGPL-2.1; no source code or real project data is reproduced here. The repository's existing harvest note remains the source for transaction-critical custom-field behavior and de-reference/delete closure. ([docs/flexicon-harvest.md:8–10](../../flexicon-harvest.md#L8-L10))

## 1. Writing systems, phonemes, codes, and boundaries

**Model.** A writing system identifies the language/script used by strings. A phoneme set holds the sound inventory; each phoneme can have one or more written codes/graphemes, and the set also holds boundary markers.

**Creation and owner.** Flexicon's writing-system method asks the manager to `Create(tag)`, registers a new definition with `Set(ws)`, then activates it with `AddToCurrentVernacularWritingSystems` or `AddToCurrentAnalysisWritingSystems`. It reuses a stored but inactive tag rather than making a duplicate. For phonemes it requires an existing set, uses the first set, rejects empty or duplicate representations, obtains `IPhPhonemeFactory`, adds the phoneme to `PhPhonemeSet.PhonemesOC`, then assigns its representation. `AddCode` creates an `IPhCode` and adds it to `phoneme.CodesOS`. `PhonemesOC` is unordered; it has no meaningful reorder API. ([WritingSystemOperations.py:192–305](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/System/WritingSystemOperations.py#L192-L305); [PhonemeOperations.py:117–249, 807–879](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/PhonemeOperations.py#L117-L249))

**Pitfalls and parser.** The phoneme factory creates a placeholder code `***`; Flexicon removes it during phoneme creation because leaving it can break HermitCrab loading. Do not set phoneme properties before attaching the object. Boundary markers are looked up in `PhPhonemeSet.BoundaryMarkersOC` when building rule contexts; the inspected rule writer does not create them. MCP's examples likewise attach a phoneme before editing it, but contain no writing-system or boundary-marker authoring recipe. ([PhonemeOperations.py:225–249, 807–879](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/PhonemeOperations.py#L225-L249); [PhonologicalRuleOperations.py:878–905](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/PhonologicalRuleOperations.py#L878-L905); [worked_examples.py:68–128](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/worked_examples.py#L68-L128))

**Unverified.** I found no phoneme-set creator in the inspected operations, so a set must already exist for this creation path. These sources also do not establish a full grapheme-phoneme mapping workflow or boundary-marker creation. Boundary markers must already exist for the cited rule-building path.

## 2. Natural classes

**Model.** A segment class lists its member phonemes. A feature class states feature constraints; phonemes matching those constraints count as members, including later-added phonemes.

**Creation and owner.** `Create` uses `IPhNCSegmentsFactory`; `CreateFeatureBased` uses `IPhNCFeaturesFactory`. Both attach to `PhonologicalDataOA.NaturalClassesOS` before setting names. The feature form places its structure in `FeaturesOA`; the segment form is populated through member references. The concrete class type cannot be switched in place. ([NaturalClassOperations.py:257–316, 803–890](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/NaturalClassOperations.py#L257-L316))

**Pitfalls and parser.** Choose the class kind before creation. Use segment membership for a deliberately fixed set and feature membership when the class should follow a property. The tools describe these classes as inputs to environment/rule notation, but their create methods do not prove a parser accepted any particular class. MCP indexes both variants. ([NaturalClassOperations.py:803–890](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/NaturalClassOperations.py#L803-L890); [flexicon_api_v4.11.0.json:49021–49052, 49228–49285](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/python/flexicon_api_v4.11.0.json#L49021-L49052))

## 3. Environments and allomorph conditioning

**Model.** A `PhEnvironment` stores a context description. An allomorph's `PhoneEnvRC` refers to one or more environments; Flexicon documents multiple environments as alternatives (OR).

**Creation and owner.** Create an `IPhEnvironment` and add it to `PhonologicalDataOA.EnvironmentsOS`, then set its `StringRepresentation`. The setter stores an `ITsString`; it does not parse or validate the notation. Flexicon's notation guide documents `_`, `#`, `$`, class abbreviations such as `V` and `C`, and `|`. Add environment references through `allomorph.PhoneEnvRC`. ([EnvironmentOperations.py:126–190, 382–442](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/EnvironmentOperations.py#L126-L190); [AllomorphOperations.py:1461–1504](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/AllomorphOperations.py#L1461-L1504))

**Pitfalls and parser.** Emptying the environment list makes the allomorph unrestricted according to Flexicon's wrapper. The local Tagalog parser probe confirms a narrower case: an infix with `PositionRS` pointing to `/# [C] _` parses `sumulat`, `sinulat`, and `bumasa`. That does not validate every notation accepted by the string setter. Optional items and the complete bracket syntax in the brief remain **Unverified**. ([Tagalog feasibility findings](../../../docs/superpowers/plans/2026-09-26-tagalog-spike-findings.md#L15-L23); [EnvironmentOperations.py:382–442](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/EnvironmentOperations.py#L382-L442))

## 4. Parts of speech, inflectable features, and inflection classes

**Model.** POS nodes classify stems and affixes. Feature structures can carry default or inherited feature values; inflection classes label inflectional patterns, and slots can refer to them.

**Creation and owner.** POS uses `IPartOfSpeechFactory`, attached either to the root `PartsOfSpeechOA.PossibilitiesOS` or a parent's ordered `SubPossibilitiesOS`. Flexicon creates inflection classes with `IMoInflClassFactory` under `MorphologicalDataOA.ProdRestrictOA.PossibilitiesOS`. Its POS helpers read `pos.InflectionClassesOC`, create slots in `pos.AffixSlotsOC`, and write `DefaultFeaturesOA` or `InherFeatValOA`. ([POSOperations.py:158–265, 810–847, 897–960, 1835–1918](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/POSOperations.py#L158-L265); [InflectionFeatureOperations.py:152–261](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/InflectionFeatureOperations.py#L152-L261))

**Pitfalls and parser.** Attach a POS before setting it. There is an unresolved ownership mismatch in the inspected API: the class creator writes to the project production-restriction list while the POS getter reads a per-POS collection. I found no corresponding writer that assigns classes to a POS, no setter for a POS's default inflection class, and no authoring path for an “inflectable feature” allowlist; treat these as **Unverified**. MCP's LibLCM index confirms `DefaultInflectionClassRA` exists, but its indexed wrappers offer no setter. For parser use, MSA/slot/class compatibility matters: Flexicon warns that HermitCrab rejects a stem/class combination if its affix MSA is not attached to a slot whose class restrictions match. ([MSAOperations.py:391–445](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/MSAOperations.py#L391-L445); [liblcm_api_v11.0.0.json:284455–284510](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/liblcm/liblcm_api_v11.0.0.json#L284455-L284510))

## 5. Entries, senses, and morph types

**Model.** An entry owns its lexeme form and senses. Morph type distinguishes stem, root, bound stem/root, prefix, suffix, infix, circumfix, and proclitic/enclitic forms; it also determines which allomorph class is created.

**Creation and owner.** `LexEntry.Create` creates an entry, selects `IMoStemAllomorphFactory` for stem-like types or `IMoAffixAllomorphFactory` otherwise, attaches the result to `LexemeFormOA`, then writes form and morph type. It creates a blank sense by default. `AddSense` delegates to sense creation and appends to `SensesOS`. ([LexEntryOperations.py:140–248, 1815–1853](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/LexEntryOperations.py#L140-L248))

**Pitfalls and parser.** Form and morph type are separate fields. For a later allomorph, the factory again depends on morph type; if omitted, the type is inherited from the entry's lexeme form and creation fails when that value is absent. A blank sense is convenient but not required. The local parser probe confirms ordinary infix entries work; the indexed reduplication form described below is a distinct parser limitation. ([AllomorphOperations.py:244–345](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/AllomorphOperations.py#L244-L345); [TagalogFeasibilityTests.cs:30–50, 133–169](../../../tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs))

## 6. Morphosyntactic analyses (MSAs)

**Model.** A sense's MSA says how its entry behaves: stem, derivational affix, inflectional affix, or unclassified affix. A derivational MSA records input and output POS; an inflectional MSA may reference slots.

**Creation and owner.** Flexicon uses the matching MSA factory and `SandboxGenericMSA`, then sets `sense.MorphoSyntaxAnalysisRA`. The factory owner must be the enclosing `ILexEntry`, not the direct owner of a subsense. Inflectional slots are added to the MSA's `SlotsRC` reference collection after creation; the from-POS is required for derivation, while its to-POS may remain unset. ([MSAOperations.py:303–477, 1745–1773](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/MSAOperations.py#L303-L477))

**Pitfalls and parser.** Do not pass a parent sense as the factory owner for a subsense. A null POS is a supported “unspecified” state for some MSA types. HermitCrab uses the inflectional MSA's slot references and slot class restrictions when deciding whether analyses are compatible. MCP's worked recipes use these wrappers rather than hand-wiring the entry's MSA collection. ([MSAOperations.py:391–445, 1745–1773](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/MSAOperations.py#L391-L445); [worked_examples.py:190–251](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/worked_examples.py#L190-L251))

## 7. Allomorphs, environments, and infix position

**Model.** An entry can have a lexeme form and alternate allomorphs. Each allomorph has its own form and morph type; a phonological environment reference conditions where it occurs.

**Creation and owner.** Flexicon chooses stem versus affix allomorph factory, then attaches to `LexemeFormOA` when empty or appends to `AlternateFormsOS`, before setting form and `MorphTypeRA`. Environment references live in `PhoneEnvRC`; multiple references are treated as alternatives, and duplicates are allowed by the wrapper. ([AllomorphOperations.py:244–345, 1461–1504](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/AllomorphOperations.py#L244-L345))

**Unverified.** In the inspected Flexicon and MCP wrapper surfaces I found no setter/creator for allomorph `PositionRS` (infix placement), `StemNameRA`, or an explicit disjunctive ordering/rank. Do not mistake a form string such as `um` for its infix position. The local test writes `PositionRS` directly to an environment and proves that particular infix path parses through PanGloss v0.5.0; it does not establish ordering among competing allomorphs. ([TagalogFeasibilityTests.cs:133–150](../../../tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs); [FlexToolsMCP flexicon API: 3718–3966](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/python/flexicon_api_v4.11.0.json#L3718-L3966))

## 8. Inflection features and feature structures

**Model.** Closed features enumerate values; complex features group nested specifications. A feature structure attaches those selections to a particular grammar object. This is the general mechanism behind agreement and noun-class bundles.

**Creation and owner.** Flexicon creates closed or complex feature definitions under `MsFeatureSystemOA.FeaturesOC`; symbolic values use `IFsSymFeatValFactory` and belong to a closed feature's `ValuesOC`. `MakeFeatStruc` requires an owner and resolves the owner's correct property, including MSA `MsFeaturesOA`/`InflFeatsOA`, derivational `FromMsFeaturesOA`/`ToMsFeaturesOA`, POS `DefaultFeaturesOA`/`InherFeatValOA`, and allomorph `MsEnvFeaturesOA`. For an owner with multiple feature properties, use the named slot discriminator. ([InflectionFeatureOperations.py:713–881, 970–1012](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/InflectionFeatureOperations.py#L713-L881); [BaseOperations.py:1939–1998, 2708–2725](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/BaseOperations.py#L1939-L1998); [AllomorphOperations.py:656–756](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Lexicon/AllomorphOperations.py#L656-L756))

**Pitfalls and parser.** Closed features can have values; complex features cannot. Attach owned definitions/values/structures before filling their properties. The local Bantu sample note models noun-class pairs as stem features and a class-specific prefix in a template, but the inspected Python sources contain no complete agreement or Bantu-noun-class authoring/parser recipe. Treat that mapping and parser result as **Unverified by this source set**. ([docs/research/synthetic-samples/bantu.md:17](../../../docs/research/synthetic-samples/bantu.md#L17); [FlexToolsMCP feature API: 33302, 33505–33565, 34187, 34416–34470](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/python/flexicon_api_v4.11.0.json#L33302))

## 9. Affix templates and slots

**Model.** A POS owns slots and templates. The template holds ordered references to slots on prefix, suffix, proclitic, and enclitic sides; optionality belongs to a slot.

**Creation and owner.** Create an `IMoInflAffixSlot` into `pos.AffixSlotsOC` first; optional defaults to false. Create the template into `pos.AffixTemplatesOS`, then insert existing slots into its side sequence. The slot must be visible in the template POS's `AllAffixSlots`—its own or an ancestor's—and the index is checked; omitted index appends. ([POSOperations.py:897–960](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/POSOperations.py#L897-L960); [MorphRuleOperations.py:395–546](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/MorphRuleOperations.py#L395-L546))

**Pitfalls and parser.** Slot creation and template placement are separate operations. A local parser warning heuristic flags optional slots that contain affixes because the parser may consider both paths. **Unverified:** source inspection did not settle how the `Final` template marker, multiple templates, or cross-template composition affect PanGloss execution. ([grammar_scan_module.py:1037–1074](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/scan/grammar_scan_module.py#L1037-L1074); [MorphRuleOperations.py:395–546](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/MorphRuleOperations.py#L395-L546))

## 10. Phonological rules

**Model.** A regular rule has an input pattern, a structural change, and left/right contexts. Boundary markers may occur in contexts, not in the structural change.

**Creation and owner.** The public creator uses `IPhRegularRuleFactory`, attaches to `PhonologicalDataOA.PhonRulesOS`, starts inactive, and leaves rule content to `WireRule`. That method creates and attaches `IPhSegRuleRHS`, stores input in `rule.StrucDescOS`, output in `rhs.StrucChangeOS`, and left/right contexts on the RHS object. Multi-element contexts use a sequence whose members are held in the project context pool. ([PhonologicalRuleOperations.py:164–230, 872–1020](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/PhonologicalRuleOperations.py#L164-L230))

**Pitfalls and parser.** The older left/right setters deliberately throw: they targeted a simple context rather than the RHS owner, so the rule could silently fail. Replacing multi-element contexts also needs cleanup of the project-level members. **Unverified:** the inspected writer creates regular rules; the wrapper can inspect/duplicate metathesis objects, but no fresh metathesis creator was found. Iterative versus simultaneous application and rule-order consequences were not demonstrated by these sources. ([PhonologicalRuleOperations.py:640–701, 872–1020, 1350–1405](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/PhonologicalRuleOperations.py#L640-L701); [phonological_rule.py:82–100, 395–425](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/phonological_rule.py#L82-L100))

## 11. Affix processes and reduplication

**Model.** An affix process describes a morphophonological input/output transformation; indexed notation such as `[C^1][V^1]` is intended to copy matching segments. This differs from an ordinary infix allomorph with a position environment.

**Creation and owner.** Flexicon's module overview identifies `MoAffixProcess` as an entry allomorph, but I found no process creator or input/output writer in the inspected operations. FlexToolsMCP's LibLCM index exposes `MoAffixProcess.InputOS` and `OutputOS`; it has no dedicated process operation or worked example. This is a wrapper gap, not evidence of model impossibility. ([MorphRuleOperations.py:13–28](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/MorphRuleOperations.py#L13-L28); [liblcm_api_v11.0.0.json:283940–283945](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/liblcm/liblcm_api_v11.0.0.json#L283940-L283945))

**Parser.** The pinned PanGloss 0.6.0 reports that `[C^1][V^1]` cannot be loaded as an affix rule or checked against the phoneme inventory; `susulat` has no reading. Motif keeps those diagnostics with unavailable morphology and correctness evidence, so the result is not reported as a completed grammar gap. The integration test asserts this outcome, or a covered reading if a later pin supports the pattern. The same fixture parses `um` and `in` infixes authored with a position environment. ([TagalogFeasibilityTests.cs](../../../tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs))

## 12. Co-prohibitions, exception features, and compounds

**Model.** Compound rules distinguish endocentric from exocentric compounds. Ad-hoc co-prohibitions constrain combinations; phonological rule contexts can also carry plus/minus feature constraints. Those context constraints are not evidence of a morphological exception-feature workflow.

**Creation and owner.** Flexicon creates a compound shell with `IMoEndoCompoundFactory` or `IMoExoCompoundFactory` under `MorphologicalDataOA.CompoundRulesOS`. The creator writes only name and optional description. Its API lists ad-hoc co-prohibitions under `MoMorphData.AdhocCoProhibitionsOC`, but the inspected methods enumerate and delete them rather than create one. The MCP index describes constraint fields, but supplies no exception-feature authoring recipe. ([MorphRuleOperations.py:78–80, 301–392, 599–602](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/MorphRuleOperations.py#L301-L392); [liblcm_api_v11.0.0.json:284605–284635](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/liblcm/liblcm_api_v11.0.0.json#L284605-L284635))

**Unverified.** No compound-member/side wiring, co-prohibition creation, or exception-feature workflow was found. The source does not establish that a created compound shell is parser-ready.

## 13. Texts and wordforms

**Model.** A `Text` with paragraphs is the corpus input. Wordforms are separate repository objects and do not, by themselves, make a corpus text or parser analysis.

**Creation and owner.** In LCM 11, Flexicon notes `IText` is unowned and auto-registered by its factory; `ILangProject.Texts` is a derived read-only list. The creator then makes an `IStText` and assigns it to `Text.ContentsOA`; paragraph creation appends an `IStTxtPara` to `ContentsOA.ParagraphsOS`. `IWfiWordformFactory` similarly registers its result automatically; Flexicon sets the wordform string but does not deduplicate it. ([TextOperations.py:117–198](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/TextsWords/TextOperations.py#L117-L198); [ParagraphOperations.py:159–225](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/TextsWords/ParagraphOperations.py#L159-L225); [WordformOperations.py:167–216](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/TextsWords/WordformOperations.py#L167-L216))

**Parser.** Motif's local feasibility path assesses a saved `Text` by GUID; it confirms the corpus route for the tested infixes and reduplication case. FlexToolsMCP indexes Text/Wordform creators but has no example of an end-to-end parser corpus workflow. ([TagalogFeasibilityTests.cs:30–50, 217–256](../../../tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs); [flexicon_api_v4.11.0.json:74131, 74381, 80567, 80684](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/index/python/flexicon_api_v4.11.0.json#L74131))

## 14. Parser behavior, performance, and grammar-health checks

**What the tools can show.** FlexToolsMCP's grammar-health handler runs a static project scan. The inspected checks count zero-surface allomorphs, flag optional slots that have affixes, empty-input regular rules, unbounded quantifiers, affix-process/phonological-rule combinations, and rules sharing a stratum pair with ordering concerns. The scan does not run PanGloss in-process. It reports risks to inspect, not parse outcomes. ([grammar_health.py:194–212, 273](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/handlers/grammar_health.py#L194-L212); [grammar_scan_module.py:252–291, 418–468, 580, 630–666, 680–744, 862–968, 1037–1074](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/scan/grammar_scan_module.py#L252-L291))

**Measured local parser evidence.** The task brief reports that 160 empty object-affix allomorphs changed neither measured work (1,723) nor steps (158) in one synthetic Bantu grammar, while duplicating real `m-`/`wa-` affixes increased work 19.5×. I did not find a retained run artifact for those measurements in the worktree, so record them as a bounded observation from the brief, not an independently reproducible result or a universal performance rule. The local guide's advice that empty affixes can add paths is therefore a risk claim, not a guaranteed effect for every grammar. ([why-a-grammar-is-slow.md:3–9](../../../help/en/guide/learn/why-a-grammar-is-slow.md#L3-L9); [parser-check SPEC.md:1426–1462, 1444–1453](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/specs/parser-check/SPEC.md#L1426-L1462))

**Unverified.** A static count or risk scan does not prove that a flagged form is reachable in an optional or repeating position, nor that removing it will improve parsing. The local brief's benchmark has no checked-in fixture or command transcript in this worktree.

## FLExTools and flexlibs: where the writer lives

FLExTools' module framework defines a `Main`-style module entrypoint; its bundled modules illustrate reports and project transformations, rather than a general grammar-authoring object model. The sample `Merge_Senses` module explicitly handles entries with missing MSAs, a useful reminder that real projects can be incomplete. ([__Template.py:1–48](https://github.com/cdfarrow/flextools/blob/b22d4141c8e598270096d4404c1b524cff83daf7/FlexTools/Modules/Examples/__Template.py#L1-L48); [Merge_Senses.py:70–96](https://github.com/cdfarrow/flextools/blob/b22d4141c8e598270096d4404c1b524cff83daf7/FlexTools/Modules/Duplicates/Merge_Senses.py#L70-L96))

flexlibs' `FLExProject` wraps opening/closing, repository enumeration, POS reads, and convenience setters for lexeme forms, examples, glosses, and custom-field text. It also exposes the LibLCM service locator and repositories, so a custom module can drop below those conveniences. This explains why the grammar-specific create/order knowledge is concentrated in Flexicon, while MCP indexes both the wrappers and LibLCM shapes. ([FLExProject.py:197–266, 452–465, 523–563, 676–803, 1060–1102](https://github.com/cdfarrow/flexlibs/blob/3ee88f536945037671a94fde9a42ce0936865d41/flexlibs/code/FLExProject.py#L197-L266))

Flexicon also has a `ReversalIndexEntry.Create` path: it attaches a top-level entry to `index.EntriesOC`, then may add a sense reference to `SensesRS`. Its creator does not accept a parent subentry. That confirms the existing harvest's description of reversal-entry ownership at the Python-tool level; the older note's “no operation family” statement is specifically about Motif's operation vocabulary, not Flexicon. ([ReversalIndexEntryOperations.py:131–221](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Reversal/ReversalIndexEntryOperations.py#L131-L221); [docs/flexicon-harvest.md:12–18](../../flexicon-harvest.md#L12-L18))

## Contradictions

1. **The parser-check spec and its zero-surface scan disagree about reachability.** The spec defines the row as a zero-surface morph reachable from an optional slot or self-looping position. The implementation deliberately accepts no reachability input and counts every zero-surface `IMoForm` project-wide. The implementation's own comment records the deferred reachability walk. Treat the emitted count as an inventory, not a parser-risk count with proven reachability. ([SPEC.md:1444–1453](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/specs/parser-check/SPEC.md#L1444-L1453); [grammar_scan_module.py:252–280, 418–439, 467](https://github.com/MattGyverLee/FlexToolsMCP/blob/4d5474a1bae1944be238448e8ff4cc6f826f856c/src/flextoolsmcp/server/scan/grammar_scan_module.py#L252-L280))

2. **General empty-affix guidance and one measured grammar point in different directions.** The Motif help page says an empty affix can add non-consuming paths. The task brief's synthetic measurement reports no measurable work change from 160 empty object-affix allomorphs in one grammar, but no benchmark artifact was found in the checkout. Keep the help statement conditional and retain the benchmark's scope and missing provenance until the run can be reproduced. ([why-a-grammar-is-slow.md:3–9](../../../help/en/guide/learn/why-a-grammar-is-slow.md#L3-L9); task brief's measurement, checked against the local source inventory)

3. **Inflection-class APIs disagree on the apparent collection.** Flexicon's creator adds classes to the project-level production-restrictions list, while its POS getter reads `PartOfSpeech.InflectionClassesOC`. I found no bridge/writer resolving the gap. This may reflect distinct global and per-POS roles, so it is a code-path discrepancy rather than proof of a data bug; assignment and default-class semantics remain **Unverified**. ([InflectionFeatureOperations.py:152–261](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/InflectionFeatureOperations.py#L152-L261); [POSOperations.py:810–847](https://github.com/MattGyverLee/flexicon/blob/d0a794c2da96e4029b875ce4e0f129d3461e7b9d/flexicon/code/Grammar/POSOperations.py#L810-L847))
