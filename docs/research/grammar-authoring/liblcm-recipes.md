# LibLCM grammar authoring recipes

This guide describes how FieldWorks/LibLCM objects become a HermitCrab grammar, and where the current PanGloss `.fwdata` reader differs. It is intended to help an author make grammar state that survives the loader and is useful to the parser.

The recipes follow the live FieldWorks `HCLoader` and its tests. PanGloss compiles its own project snapshot; it does not call the C# loader. A feature that loads in `HCLoader` is therefore not automatically consumed by PanGloss. `FieldWorks/`, `PanGloss/`, `Machine/`, and `liblcm/` below are paths relative to the sibling checkouts `C:\Users\johnm\Documents\repos\FieldWorks`, `C:\Users\johnm\Documents\repos\PanGloss`, `C:\Users\johnm\Documents\repos\machine`, and `C:\Users\johnm\Documents\repos\liblcm`. Motif paths are relative to this repository. The cited fixtures are synthetic; no real project data is reproduced here.

## Authoring order and shared setup

Build dependencies before their references: select the default vernacular writing system; establish phonemes, codes, and boundaries; define feature systems and natural classes; define environments and parts of speech; then create entries, allomorphs, MSAs, slots, templates, rules, and any text used to exercise them. Motif’s sample seeder follows that dependency order inside one unit of work (tools/SampleProjects/Program.cs:572-592). The factories are obtained from the supplied cache’s service locator; the cache and its persistence remain the caller’s responsibility.

The parser parameter value is XML on `MorphologicalDataOA.ParserParameters`. HCLoader reads options under `<HC>` including `NoDefaultCompounding`, `NotOnClitics`, `AcceptUnspecifiedGraphemes`, and custom `<Strata>` text; it reads per-compound `maxApps` from `<CompoundRules>` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:92-112). FieldWorks `MoStratum` objects and `StratumRA` references are not the same thing as the `<Strata>` setting: the C# loader reorganizes its grammar from that text (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:359-494), while PanGloss retains the text but currently warns and uses its default strata (PanGloss/rust/crates/pg-fwdata/src/parser_params.rs:121-124; PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:352-378).

## 1. Writing systems, phoneme inventory, and boundaries

**Meaning.** The phoneme inventory says which segments the parser recognizes and how each one is spelled. Boundaries let rules refer to word or morpheme edges.

**LibLCM recipe.** Put the language’s vernacular writing system first in `WritingSystems.CurrentVernacularWritingSystems`; set forms and codes in `cache.DefaultVernWs`. Make an `IPhPhonemeSet` with `IPhPhonemeSetFactory` under `PhonologicalDataOA.PhonemeSetsOS`, then `IPhPhoneme` objects from `IPhPhonemeFactory` under `PhonemesOC`. Give each parser-visible phoneme at least one `IPhCode` from `IPhCodeFactory` in `CodesOS`, with its vernacular `Representation`. Put boundary markers from `IPhBdryMarkerFactory` under that same set’s `BoundaryMarkersOC`, with codes as well (tools/SampleProjects/Program.cs:685-699,736-765).

**Pitfalls and parser effect.** HCLoader builds its character table from only `PhonemeSetsOS[0]`. It uses vernacular code representations; a phoneme with no usable code is logged and omitted, and a duplicate grapheme is logged and not mapped (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:204,2669-2696). It ignores the special word-boundary marker GUID, then adds its own internal boundaries (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2698-2715). A segment natural class containing an omitted phoneme will fail as a whole when first loaded (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2788-2817). PanGloss also selects only the first set, but its importer reports extra sets as a warning (PanGloss/rust/crates/pg-fwdata/src/extract/phonology.rs:61-105). Multiple sets and level-specific inventories are not reachable through this loader contract.

## 2. Natural classes: segment lists and feature descriptions

**Meaning.** A segment class is an enumerated set of phonemes. A feature class describes a set by its phonological feature structure.

**LibLCM recipe.** Create `IPhNCSegments` with `IPhNCSegmentsFactory`, add it to `PhonologicalDataOA.NaturalClassesOS`, and add members to `SegmentsRC` (tools/SampleProjects/Program.cs:768-784). For an intensional class, create `IPhNCFeatures` with `IPhNCFeaturesFactory` in the same owner sequence and set its `FeaturesOA` structure. A feature class uses the phonological feature system, not the morphosyntactic one (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:193-211,430-447).

**Pitfalls and parser effect.** Class names are for people; parser references use the actual object. Ensure every segment member has a unique, recognized phoneme code. HCLoader caches a failed segment class as null, so references to that class do not become an empty or partial set (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2788-2829). PanGloss compiles both segment and feature natural classes (PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:13-17).

## 3. Phonological environments and validation

**Meaning.** An environment constrains where a stem or affix allomorph can occur; an infix’s position environment constrains where its material is inserted.

**LibLCM recipe.** Create an `IPhEnvironment` with `IPhEnvironmentFactory` under `PhonologicalDataOA.EnvironmentsOS`; set `StringRepresentation` in the vernacular writing system. HCLoader reads and validates that string. The `PhEnvironment` structured context graph is not the input to this environment path (tools/SampleProjects/Program.cs:786-799; FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1177-1224; docs/hc-surface-scope.md:79-83). Use the recognizer’s `/ left _ right` form with known segments/classes. The checked fixture accepts a space-containing form with `[C]`, optional `([V])`, and `#` (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:541-560).

**Pitfalls and parser effect.** Attach ordinary allomorph contexts through `IMoAffixAllomorph.PhoneEnvRC`; attach infix placement through `PositionRS`. HCLoader validates both but uses them differently (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1167-1175). An invalid stem context is logged and omitted (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:815-829). For affixes, `GetValidEnvironments` logs an invalid context and also yields a blank environment alternative; this can lose the restriction and broaden the allomorph, so a successful load is not proof of a valid condition (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1177-1197). PanGloss emits load warnings for malformed environments; check the assessment’s load warnings instead of assuming the condition was honored.

## 4. Parts of speech and inflection classes

**Meaning.** Parts of speech constrain syntactic use. Inflection classes divide members of a part of speech into inflectional subclasses. A POS’s inflectable-feature list declares the dimensions its words can inflect for; child POSes inherit the parent’s list.

**LibLCM recipe.** Create each `IPartOfSpeech` with `IPartOfSpeechFactory` under `LangProject.PartsOfSpeechOA`. Create feature definitions under `LangProject.MsFeatureSystemOA.FeaturesOC`, then add applicable definitions to `IPartOfSpeech.InflectableFeatsRC`; FieldWorks’ editor performs that addition, and the generated interface documents inherited features (FieldWorks/Src/LexText/Morphology/MGA/MasterInflectionFeature.cs:86; liblcm/src/SIL.LCModel/GeneratedInterfaces.cs:10180-10196). Create each `IMoInflClass` with `IMoInflClassFactory` and add it to the owning POS’s `InflectionClassesOC`. Link a stem’s `IMoStemMsa.PartOfSpeechRA`; use `InflectionClassRA` when the stem belongs to an explicit subclass. Motif’s sample builder assigns the first created class to `DefaultInflectionClassRA` only when no default is already set (tools/SampleProjects/Program.cs:595-624,718-727).

**Pitfalls and parser effect.** Do not confuse a convenient sample-seeder default with an LCModel rule that every POS must have a default. HCLoader uses the stem MSA’s explicit class first; if absent, it searches the POS and its ancestors for `DefaultInflectionClassRA` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2625-2648). No class found means no inferred inflection-class restriction. POS and inflection class are also represented in HCLoader feature/MPR systems (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:168-177).

## 5. Entries, senses, and morph types

**Meaning.** A lexical entry groups a lexical item’s forms, analyses, and senses. A sense supplies a gloss; a morph type tells the loader whether a form is a stem, prefix, suffix, infix, clitic, or another supported form kind.

**LibLCM recipe.** Create an `ILexEntry` with `ILexEntryFactory` under `LexDbOA`; store the primary form in `LexemeFormOA`, variants in `AlternateFormsOS`; put analyses in `MorphoSyntaxAnalysesOC` and senses in `SensesOS`. Link `ILexSense.MorphoSyntaxAnalysisRA` to the intended MSA. Create stem or affix forms with `IMoStemAllomorphFactory` or `IMoAffixAllomorphFactory`; set `IMoForm.MorphTypeRA` using `IMoMorphTypeRepository`, and put vernacular text in `Form`. Create the sense with `ILexSenseFactory` and set its MSA reference (tools/SampleProjects/Program.cs:701-734,849-890; tests/SIL.Motif.Tests.Support/TestFixtures/SeededProject.cs:222-243).

For a circumfix, mark the entry with the circumfix morph type and keep the prefix and suffix halves as separate `IMoAffixAllomorph`s in its alternate-form sequence. HCLoader pairs each valid prefix and suffix with their environments (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:632-649; FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1048-1082). Root and stem forms are `IMoStemAllomorph`s; a bound root or stem sets the loaded HC allomorph’s `IsBound` flag (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:809-841; test FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:793-824). Clitic and particle forms load as entries in the clitic stratum; an enclitic can also be a rule form (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:848-919).

**Pitfalls and parser effect.** Empty or abstract forms are filtered. Stem entries need a recognized stem or clitic morph type; an affix with a bracket pattern needs a valid phone environment in several prefix/suffix cases; infixes need a valid `PositionRS` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:536-568,579-589). A missing morph type filters a form from the stem and affix paths (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:536-568,579-589; tests FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:665-673,826-834). A missing MSA/sense association can leave an object in the project without the intended parser analysis. The loader obtains parser glosses from senses, not `MoGlossItem` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:910-913). PanGloss classifies forms through its own import/compiler path (PanGloss/rust/crates/pg-grammar/src/compile/lexicon.rs:101-155).

## 6. Morphosyntactic analyses

**Meaning.** The MSA says what a form does grammatically. Stem, inflectional, derivational, and unclassified affix analyses carry different inputs and effects.

**LibLCM recipe.** Each MSA is owned by `entry.MorphoSyntaxAnalysesOC`. For a stem use `IMoStemMsa` from `IMoStemMsaFactory`; set `PartOfSpeechRA`, optional `InflectionClassRA`, and optional `MsFeaturesOA` (tools/SampleProjects/Program.cs:718-727). For an inflectional affix use `IMoInflAffMsa` from `IMoInflAffMsaFactory`; set `PartOfSpeechRA`, `InflFeatsOA`, any production restrictions, and `SlotsRC` to identify template slots (tools/SampleProjects/Program.cs:878-885; FieldWorks/Src/LexText/ParserCore/HCLoader.cs:976-1005). A derivational MSA uses `IMoDerivAffMsa` from `IMoDerivAffMsaFactory`, with `FromPartOfSpeechRA`, `ToPartOfSpeechRA`, from/to feature structures and classes; FieldWorks’ importer uses that factory (FieldWorks/Src/LexText/LexTextControls/LiftMergerSupportCodeAndClasses.cs:4330-4342), and HCLoader maps these fields to required and output syntactic/MPR features (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:926-974). For unclassified affixes, the checked Motif test uses the `ILexEntryFactory.Create(..., SandboxGenericMSA)` convenience route with `MsaType.kUnclassified`, and FieldWorks’ loader test exercises that analysis type (tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs:203-214; FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:652-673). A direct `IMoUnclassifiedAffixMsaFactory` creation recipe was not found: that factory route is **Unverified**. HCLoader supports an unclassified MSA as a partial rule with an optional POS requirement (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1008-1028).

**Pitfalls and parser effect.** An inflectional MSA with one or more slots is reached from its template, not also from the ordinary rule list, to prevent double application (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:847-924; PanGloss does the same at PanGloss/rust/crates/pg-grammar/src/compile/lexicon.rs:140-155). With no slots, HCLoader treats the inflectional MSA as partial. Do not model derivation as an inflectional affix with a changed gloss: from/to POS and feature structures define the grammatical change. Unsupported MSA subclasses should be treated as unverified, not silently approximated as one of these four.

## 7. Allomorphs, environments, order, infixation, and stem names

**Meaning.** Allomorphs are alternative realizations of a morpheme, often conditioned by phonological or grammatical context. Their order may encode disjunctive blocking, not just display order.

**LibLCM recipe.** Create `IMoStemAllomorph` with `IMoStemAllomorphFactory` for a stem and `IMoAffixAllomorph` with `IMoAffixAllomorphFactory` for a concatenative affix. The primary form is `LexemeFormOA`; other forms are in `AlternateFormsOS`. Link contexts in `PhoneEnvRC`; for an infix, use `PositionRS`. An inflectional affix allomorph can have `InflectionClassesRC` and `MsEnvFeaturesOA` (tools/SampleProjects/Program.cs:701-717,849-877). For a stem name, create `IMoStemName` with `IMoStemNameFactory` under the POS and supply nonempty `RegionsOC` feature structures; link it from `IMoStemAllomorph.StemNameRA` (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:339-358; loader at FieldWorks/Src/LexText/ParserCore/HCLoader.cs:206-224,831-833).

**Pitfalls and parser effect.** HCLoader visits `AlternateFormsOS` before `LexemeFormOA`; Machine’s allomorph matching checks earlier alternatives and blocks a later alternative when an earlier eligible disjunct applies, except where free fluctuation allows it. Preserve that order deliberately (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:256-284; Machine/src/SIL.Machine.Morphology.HermitCrab/Allomorph.cs:127-147; Machine/src/SIL.Machine.Morphology.HermitCrab/MorphologicalRules/SynthesisAffixProcessRule.cs:214-221). Empty/all-invalid stem-name regions produce no loaded stem name (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:206-224). HCLoader handles circumfix halves by cross-producting prefix, suffix, and their environments (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1048-1082); see the current PanGloss caveat under Contradictions.

## 8. Closed features, values, feature structures, and agreement

**Meaning.** A closed feature has a declared set of values. Feature structures put those values on sounds, lexical analyses, allomorph constraints, or rule contexts; alpha variables express shared feature values across a rule.

**LibLCM recipe.** Create morphosyntactic closed features under `LangProject.MsFeatureSystemOA.FeaturesOC` with `IFsClosedFeatureFactory`, and values under `ValuesOC` with `IFsSymFeatValFactory`. Build an `IFsFeatStruc` with `IFsFeatStrucFactory`; add `IFsClosedValue` entries to `FeatureSpecsOC` and link `FeatureRA` and `ValueRA` (tools/SampleProjects/Program.cs:627-672). Phonological features belong to `PhFeatureSystemOA`; attach them to phonemes or `IPhNCFeatures.FeaturesOA`. For syntax, stem features go on `IMoStemMsa.MsFeaturesOA`, inflection requirements on `IMoInflAffMsa.InflFeatsOA`, and allomorph requirements on `IMoAffixAllomorph.MsEnvFeaturesOA` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:718-727,872-883; loader mappings FieldWorks/Src/LexText/ParserCore/HCLoader.cs:985-1003,1111-1129,2650-2667).

**Pitfalls and parser effect.** Names and abbreviations do not substitute for `FeatureRA`/`ValueRA` references. HCLoader maps closed values by object identity; a missing/unknown value is skipped without a user-facing feature-structure error (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2500-2529). Agreement in a phonological rewrite uses `IPhFeatureConstraint` variables referenced from contexts; HCLoader assigns a fixed set of 24 variable names, so more than 24 constraints is unsafe (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:2003-2011; PanGloss/rust/crates/pg-grammar/src/compile/rules.rs:14-19). For a Bantu-style noun-class paradigm, a closed morphosyntactic feature with one value per class is a plausible representation, but the checked fixtures do not prove a complete noun-class agreement grammar. That recipe remains **Unverified**; test MSA compatibility, affix selection, and surface outputs in a synthetic project before relying on it.

## 9. Inflectional templates and slots

**Meaning.** A template gives an inflectional category a sequence of positions. Each slot can admit competing affixes and can be optional.

**LibLCM recipe.** Create `IMoInflAffixSlot` with `IMoInflAffixSlotFactory` under the owning POS’s `AffixSlotsOC`, setting `Optional`. Create `IMoInflAffixTemplate` with `IMoInflAffixTemplateFactory` under `AffixTemplatesOS`, set `Final`, and add slot references in sequence to `PrefixSlotsRS` or `SuffixSlotsRS`. Link each inflectional MSA to the relevant slot through `SlotsRC` (tools/SampleProjects/Program.cs:801-835,878-885; FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:729-768).

**Pitfalls and parser effect.** The LCModel stores prefix and suffix sequences separately; HCLoader flattens them as suffix slots followed by reversed prefix slots. A slot is kept only if at least one linked affix MSA survived loading; an empty result means the template is omitted (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:295-300,1673-1790). Preserve each sequence’s order and optionality. HCLoader enumerates all non-disabled templates, but the inspected Motif and HCLoader fixtures do not pin the interaction/order of multiple templates for one POS; that behavior is **Unverified** here. PanGloss builds templates and synthesizes null affixes for irregular required slots (PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:13-17).

## 10. Phonological rewrite rules and metathesis

**Meaning.** A regular rule maps an input pattern to a changed output pattern under contexts. Iterative direction and simultaneous application change how repeated matches are processed. Metathesis swaps material in a structural description.

**LibLCM recipe.** Create `IPhRegularRule` with `IPhRegularRuleFactory` in `PhonologicalDataOA.PhonRulesOS`. Put the left side in ordered `StrucDescOS`, alternatives in `RightHandSidesOS`, and each RHS’s output in ordered `StrucChangeOS`. Add left/right contexts, input POS, required/excluded rule features as needed. `Direction` 0 is left-to-right iterative, 1 right-to-left iterative, and 2 left-to-right simultaneous. HCLoader visits enabled rules ordered by `OrderNumber` (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:1072-1120; FieldWorks/Src/LexText/ParserCore/HCLoader.cs:302-320,2003-2100).

For metathesis, create `IPhMetathesisRule` with `IPhMetathesisRuleFactory` and give it a complete structural description and both switch indices; the loader checks those indices before constructing the rule (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:322-335,2103-2160; test FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:1122-1170).

**Pitfalls and parser effect.** A regular rule with no structural description and no RHS structural change is skipped before conversion (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:306-312). Empty/unloadable rules may also be omitted. Rule order is `OrderNumber`, not object enumeration order. The C# loader can build metathesis; current PanGloss logs and skips it (PanGloss/rust/crates/pg-grammar/src/compile/rules.rs:57-70). PanGloss’s rewrite-rule compiler should therefore be distinguished from its metathesis support.

## 11. Affix processes, reduplication, and infixation

**Meaning.** An affix process describes a transformation over an input sequence. Reduplication copies part of that input; infixation inserts material at a position inside the stem.

**LibLCM recipe.** Replace the entry form with `IMoAffixProcess` from `IMoAffixProcessFactory`. Preserve order in `InputOS` and `OutputOS`. Inputs can include phonological contexts and variables. The HCLoader output mappings are `IMoCopyFromInput`, `IMoInsertPhones`, `IMoInsertNC`, and `IMoModifyFromInput`; the referenced input position is derived from its index in `InputOS` (FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:1172-1230; FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1334-1438).

For bracket-pattern reduplication, forms such as `[C^1][V^1]-` are interpreted by the C# loader as indexed pattern pieces and output actions (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1441-1480,1570-1672). For an ordinary infix, use `IMoAffixAllomorph` with infix `MorphTypeRA`, `PositionRS` pointing at a valid environment, and an inflectional MSA/slot if it is inflectional. The Motif sample test checks the infix type and position reference and parses a synthetic `sumulat` word (tests/SIL.Motif.Tests.LibLcm/Samples/SampleBuilderInfixTests.cs:32-38,45-75,97-111).

**Pitfalls and parser effect.** HCLoader rejects an affix process with an empty or unusable side; a plain infix without a valid position environment is filtered (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:536-540,562-565; FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:504-539,1232-1276). PanGloss v0.5.0 still rejects bracket-pattern reduplication with a warning, while Motif’s Tagalog feasibility test deliberately skips the real-parser reduplication assertion for that reason (PanGloss/rust/crates/pg-grammar/src/compile/affixes.rs:809-829; tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs:38-43). The same test exercises an infix parse (tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs:27-36). Do not infer PanGloss’s reduplication support from the C# loader’s.

## 12. Co-prohibitions, exception features, and compounding

**Meaning.** Co-prohibitions prevent selected allomorphs or morphemes from co-occurring at a chosen distance. Production-restriction possibilities act as exception/MPR features. Compound rules constrain the head and non-head and may set an output POS.

**LibLCM recipe.** Define production-restriction possibilities with `ICmPossibilityFactory` under `MorphologicalDataOA.ProdRestrictOA`; reference them from the MSA or relevant rule. Create `IMoAlloAdhocProhib` with `IMoAlloAdhocProhibFactory` and `FirstAllomorphRA`, `RestOfAllosRS`, and `Adjacency`, or `IMoMorphAdhocProhib` with `IMoMorphAdhocProhibFactory` and the analogous MSA references. The loader maps adjacency values 0–4 to anywhere, left, right, adjacent-left, and adjacent-right (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:179-186,2163-2258; setup FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:339-346,1032-1070). Compound rules use `IMoEndoCompoundFactory` or `IMoExoCompoundFactory`, link left/right MSAs, head direction and an overriding/to MSA, and belong to `MorphologicalDataOA.CompoundRulesOS` (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:1842-1905; tests FieldWorks/Src/LexText/ParserCore/ParserCoreTests/HCLoaderTests.cs:923-1008).

**Pitfalls and parser effect.** Co-prohibitions are loaded only when enabled and when the first target plus at least one rest target exist. If any referenced target failed to load, HCLoader returns without attaching the rule (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:341-350,2163-2239). Unknown/missing exception feature references therefore undermine the intended restriction. If there are no compound rules, FieldWorks may insert defaults unless `NoDefaultCompounding` is true; authored disabled rules are skipped (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:235-253). PanGloss compiles authored/default compounding and co-occurrence rules, but validate its load warnings for dangling IDs.

## 13. Texts and wordforms

**Meaning.** Text data supplies words for parser assessments. Wordforms connect a segment in a text with a form and, when present, one or more analyses.

**LibLCM recipe.** Create `IText` with `ITextFactory`, attach `IStText` from `IStTextFactory` as `ContentsOA`, add `IStTxtPara` from `IStTxtParaFactory` to `ParagraphsOS`, create `ISegment` with `ISegmentFactory` in `SegmentsOS`, then create `IWfiWordform` with `IWfiWordformFactory` and add it to `segment.AnalysesRS`. The sample builder stores paragraph contents and wordforms; the test fixture can build approved analysis bundles (tools/SampleProjects/Program.cs:894-929; tests/SIL.Motif.Tests.Support/TestFixtures/SeededProject.cs:134-220).

**Pitfalls and parser effect.** A wordform alone is not proof of an approved morphological analysis. Keep the segment text, writing system, and wordform aligned with the grammar; otherwise a parser run may report the word as unanalyzed without indicating which authoring link was missed. Motif’s sample builder deliberately creates bare wordforms; the seeded test fixture is the source for examples needing a full analysis bundle (tests/SIL.Motif.Tests.Support/TestFixtures/SeededProject.cs:212-220).

## 14. Parser behavior, performance, and diagnostics

**Meaning.** A usable grammar needs more than model objects: load-time filtering, warnings, rule order, and search branching affect the parse and the explanation an author can give for it.

**Observed behavior.** HCLoader loads a constrained model in a fixed sequence: feature systems and first phoneme set, entries/forms, templates, ordered phonological rules, and co-occurrence rules (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:164-355). Failed forms, empty templates, invalid segment references, and missing co-occurrence targets can disappear or lose constraints. PanGloss’s direct `.fwdata` route instead imports a snapshot and returns load warnings; use those warnings as part of an assessment, not as incidental console noise (PanGloss/rust/crates/pg-cli/src/main.rs:400-435).

**Performance evidence and limitation.** The shared task brief reports that adding 160 empty object-affix allomorphs changed neither 1,723 parser work units nor 158 steps, while duplicating real `m-`/`wa-` affixes increased work 19.5× (temporary task source `C:/Users/johnm/AppData/Local/Temp/claude/C--Users-johnm-Documents-repos-motif/c0828612-055c-4fe6-b94c-0b4b589e4b85/scratchpad/guide-common.md:38-39`). I found no checked-in benchmark harness or result artifact for those numbers, so preserve them as an unverified local observation, not a general performance law. The current guide says empty affixes can add paths (help/en/guide/learn/why-a-grammar-is-slow.md:3-9); the measurement and the general warning are not necessarily incompatible because identity, environment, templates, and ambiguity differ, but this is not established by the checked-in evidence.

**Diagnostics recipe.** First check the project’s writing-system/code map, then load warnings, then whether the relevant entry/MSA/allomorph/template survived, then the assessed word and its alternatives. PanGloss also has a separate `pangloss grammar-health` report. Its authoring checks report undeclared segments (warning), duplicate feature bundles, stems without a category, inflectional affixes without a template slot, unclassified affixes, and partial morphemes with unknown reasons (error findings); it merges importer warnings into the JSON and text report (`PanGloss/rust/crates/pg-grammar/src/grammar_health.rs:46-83,133-166,1000-1008`; CLI `PanGloss/rust/crates/pg-cli/src/grammar_health.rs:72-107`). This command is distinct from `fst-health`: authoring checks inspect a loaded grammar and do not change its parse, while the CLI returns a nonzero result when error-level findings exist (`PanGloss/rust/crates/pg-grammar/src/grammar_health.rs:1-12`; `PanGloss/rust/crates/pg-cli/src/grammar_health.rs:5-10,98-107`). Change one conditioning relation at a time. Do not use a successful parse to certify that all restrictions loaded: the invalid-affix-environment fallback can broaden the rule. For expensive parses, use Motif Timing to locate recorded work by rule and word; compare controlled grammar variants rather than assuming every empty or optional object has equal cost.

## Contradictions and corrections

1. docs/hc-surface-scope.md:45-50 and PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:19-23 say current PanGloss lacks circumfix cross-products and clitic-as-affix/stem roles. Current code implements circumfix cross-products (PanGloss/rust/crates/pg-grammar/src/compile/affixes.rs:483-525) and puts enclitic entries and rules into clitic buckets (PanGloss/rust/crates/pg-grammar/src/compile/lexicon.rs:108-155); tests pin conditioned circumfix cross-product parsing (PanGloss/rust/crates/pg-grammar/tests/circumfix_conditioning_parity.rs:210-230) and enclitic dual treatment (PanGloss/rust/crates/pg-grammar/tests/circumfix_conditioning_parity.rs:1775-1834). Those coverage summaries are stale for these rows.
2. The same summary is right that PanGloss currently skips metathesis and bracket-pattern reduplication; the current source emits an unsupported warning for metathesis (PanGloss/rust/crates/pg-grammar/src/compile/rules.rs:57-70) and rejects bracket-pattern affixes (PanGloss/rust/crates/pg-grammar/src/compile/affixes.rs:809-829). Motif’s synthetic infix path parses, but the Tagalog reduplication path is explicitly skipped for PanGloss v0.5.0 (tests/SIL.Motif.Tests.LibLcm/Samples/TagalogFeasibilityTests.cs:24-50).
3. docs/hc-surface-scope.md:49 and PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:22-23 imply custom `<Strata>` reorganization is not supported by the current consumer. FieldWorks’ `HCLoader` does honor the setting; PanGloss’s snapshot importer stores the value, while its compiler warns and uses defaults (FieldWorks/Src/LexText/ParserCore/HCLoader.cs:92-102,359-473; PanGloss/rust/crates/pg-fwdata/src/parser_params.rs:121-124; PanGloss/rust/crates/pg-grammar/src/compile/mod.rs:352-378). Keep those two paths separate in author guidance.
4. The checked-in slow-grammar guide describes empty affixes as a source of extra paths. The task’s local timing note reports no measurable work change for its specific 160-empty-affix fixture and a large increase for duplicated real affixes. Without a checked-in benchmark or enough setup detail, this remains an unresolved scope difference, not grounds to reverse the general guide.
